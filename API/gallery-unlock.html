插件说明

给 BGM / CG 鉴赏页加「逐项解锁」：只有在剧本中被播放 / 展示过的条目才正常显示， 其余显示锁定态 —— BGM 按钮显示 ???，CG 格子盖一层黑色遮罩、居中白色大写 NO DATA。 未解锁项在鉴赏页点击不做任何事，歌单循环与 CG 放大翻页会自动跳过未解锁项。

插件在两个位置各做一件事：

  • 记录端（剧本页）：BGM 被播放、CG 被展示时，把对应条目写进 sf. 持久区， 键为 sf.gal_bgm_<条目名> / sf.gal_cg_<条目名>（值 1）， 跨存档、跨会话留存。
  • 读取端（鉴赏页）：按 sf. 里的记录给未解锁项加锁，并让列表循环 / 翻页跳过它们。

BGM 取 gameEngine.playAudio 的键（并按解析出的路径反查表名）； CG 取 gameEngine.setBackground 的背景路径与 gameEngine.eventShow 的事件图路径， 两者都按 CG_CONFIG(_SUB) 反查条目名 —— 所以事件图、以及作为背景显示的 CG 都算「展示过」。

开发者测试：置 tf.allclear（启动器调试菜单「开启全部鉴赏」， 或控制台 VarSpace.setTempAllClear(true)）时全部开放。 页面存活期间该开关被切换（含开 → 关）时掩码会立即重算，无需刷新页面； html/bgm.html 这类不注入 vars.js 的页面由低频巡检兜底（约 0.8 秒内生效）。

涉及文件

文件放置位置作用
gallery_unlock.js引擎 plugins/（目录不存在就新建）插件本体：记录端 + 读取端 + 锁定态渲染
engine_manifest.json引擎目录根在 official 列表末尾追加一项，宿主自动注入剧本页与 CG 页
html/bgm.html引擎 html/不在注入范围内，需手写一行引用

引用方式（二选一，或同时使用）

方式 1（推荐）：写进 engine_manifest.json 的 official 列表末尾

宿主（启动器）会把 official 序列自动注入剧本页（scenes/*.html）、 index.html 与 html/CG.html，这三类页面无需改文件即可生效：

{ "type": "js", "path": "plugins/gallery_unlock.js" }

方式 2：html/bgm.html 手写一行引用

html/bgm.html 不在 official 的注入范围内，需在 </body> 之前手写：

<script src="../plugins/gallery_unlock.js"></script>
两种方式覆盖不同页面：方式 1 负责剧本页的记录端与 CG 鉴赏页的读取端， 方式 2 负责 BGM 鉴赏页的读取端。要让 BGM 鉴赏页生效，方式 2 必须加。

可调开关

页面可在加载本文件之前于 window 上覆盖（均可选）：

全局变量默认值含义
SHIORI_GALLERY_UNLOCK_BGMtrueBGM 侧是否生效；false 时既不记录也不加锁
SHIORI_GALLERY_UNLOCK_CGtrueCG 侧是否生效
SHIORI_GALLERY_LOCK_TEXT_BGM'???'BGM 锁定按钮文案
SHIORI_GALLERY_LOCK_TEXT_CG'NO DATA'CG 遮罩文案（CSS 自动大写）

例：只启用 CG 侧，在引用行之前加一句：

<script>window.SHIORI_GALLERY_UNLOCK_BGM = false;</script> <script src="../plugins/gallery_unlock.js"></script>

对外 API

插件挂载 window.ShioriGalleryUnlock，供剧本 / 调试使用（鉴赏页 UI 不接它，页内不能解锁）： bgmEnabled() / cgEnabled() / allClear() / isBgmUnlocked(key) / isCgUnlocked(key) / unlockBgm(key) / unlockCg(key) / refresh()。

解锁的唯一正规途径是在剧本中播放 / 展示；unlockBgm / unlockCg 仅供剧本或调试调用。

排错：锁定态 ≠ 取图失败

CG 鉴赏页里格子「变暗且点不开」有两种互不相干的原因，控制台会分别提示：

现象判据含义
黑色遮罩 + 白色 NO DATA格子带 data-gal-locked="1"本插件判定为未解锁（剧本里没展示过）
变暗、无遮罩、点不开格子带 data-cg-missing="1"页面自己没取到缩略图，与解锁无关

后者由引擎的 CGManager._markMissing() 写入：只要宿主没能交付缩略图字节， 所有格子（含磁盘上确实存在的图）都会被标记为缺失，于是变暗并拒绝点击。 此时控制台会打印 CG图片不存在: <路径>，插件也会补一句 [GalleryUnlock] CG <路径> 已解锁，但页面未取到图（标记 missing）。

它不是插件造成的，可按顺序排查：

  1. 控制台 [CG] 批量取图 请求 N 张 → 就绪 M 张 —— 若「就绪 0」，缩略图链路整个没通；
  2. 网络面板看 /api/imgpack?keys=... —— 返回 404 说明宿主关掉了缩略图， 此时 /cg-thumb/* 同样 404；
  3. 核对 config/cg_config.js 的路径：CG_CONFIG_SUB 是给 html/ 下页面用的， 必须写成 ../assets/cg/xxx。少了 ../ 会解析到 /html/assets/... 而 404。
tf.allclear（开启全部鉴赏）打开时不应出现 NO DATA —— 那时全部条目都视为已解锁，遮罩本就该消失。要观察锁定态请先关掉它。

卸载

删掉方式 1 的 engine_manifest.json 条目与方式 2 的 <script> 行即可， 页面完全恢复为未安装插件时的样子（sf. 里已写入的 gal_* 记录可留可删，不影响其它功能）。
