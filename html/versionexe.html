V1.2.7 (2026/7/22)

1.存档文件优化
  • 1.1.现在存档文件自动创建时，会自动省略不必要的文件，以下文件大小为游戏初次运行后的大小，不含其他存档内容
    • 正式版（release）：126MB→14.4MB
    • 测试版（debug）：252MB→14.8MB
  • 1.2.新增“清除无用缓存”按钮，在“文件”菜单中，点击后会删除所有无用文件，适用于使用了V1.2.7版本前已经生成过存档文件的用户。
2.启动流程优化
  • 由于首次启动时，需要数秒的时间写入存档必须文件，且后续的需求需要，现在启动器会在启动时默认显示一个遮罩层，至少持续三秒（如果必要文件生成完毕后或引擎加载完成后可鼠标点击关闭）
    • 如何修改默认遮罩层的图片：在引擎核心的路径中：..\shiori engine\assets\cg\，创建一个名为“logo”的图片，不限制格式（比如可以使用.png，.jpg等）

    V1.2.1 (2026/5/18) — 构建流程优化与存档管理

    构建流程优化
    • 二次编译性能提升：
      • 优化 C# 项目的增量编译机制，减少不必要的重新编译步骤
      • 引入智能依赖检测，仅在源文件变更时触发完整编译
      • 典型场景下二次编译时间从 2-5 秒缩短至 1-2 秒
      • 首次编译不受影响：优化仅针对增量编译阶段，首次完整编译所需时间保持不变（约 10-20 秒，受网络影响）
    存档管理功能扩展
    • 新增一键清除存档功能：
      • 在调试版（Shiori_debug.exe）的「调试」菜单中添加「清除所有存档」按钮
      • 执行前提供二次确认对话框，防止误操作
      • 清除范围涵盖所有剧本的进度存档、选择记录等持久化数据
    • 新增存档相关问题帮助文档：
      • 在「帮助」菜单中添加「存档相关问题」选项，提供详细的存档系统说明
      • 内容涵盖：存档数据存储位置、存档类型说明、三种备份方法（手动备份文件夹/游戏内导出/云同步）、常见问题FAQ
      • 根据版本差异化显示：调试版强调清除测试数据指引，正式版突出玩家备份指南
    快捷键优化
    • 新增引擎刷新快捷键：添加 Ctrl+F5 用于强制刷新引擎
      • 保留原有 F5 快速存档功能不变
      • 避免与浏览器默认刷新行为冲突，提供更明确的刷新触发方式

    V1.2.0 (2026/5/14) — 启动器架构升级

    升级背景

    鉴于 Python 版本启动器（V1.1.X）在运行时性能及开源协议兼容性方面存在制约（PyQt6 的 GPL/LGPL 协议不适用于本开源引擎的商用分发场景），决定将运行时迁移回 C# 平台，基于 .NET 8 构建新版启动器（V1.2.X）。

    设计目标

    新版启动器（V1.2.X）采用「取其精华，去其糟粕」的演进策略，综合优化了早期 C# 版本（V1.0.X）与 Python 版本（V1.1.X）的技术路线：

    维度 V1.0.X (C#/.NET 6) V1.1.X (Python) V1.2.X (C#/.NET 8)
    图形渲染 原生浏览器内核 PyQt6 内置 WebEngine 独立窗口渲染，性能与主流浏览器无差异，较 PyQt6 内置内核实现量级提升
    二次编译耗时 10–20 秒 10–20 分钟 2–5 秒
    功能覆盖 基础功能 完整功能（含独立窗口、Debug 调试） 全量移植 Python 版本功能集
    交付体积优化

    通过 .NET 8 的 Native AOT / 裁剪编译及依赖精简策略，可执行文件体积实现显著压缩：

    构建配置 V1.0.X (C#/.NET 6) V1.1.X (Python) V1.2.X (C#/.NET 8)
    正式版（Release） 30 MB+ — —
    正式版 + Debug 符号 — 700 MB+ 200 MB+

    注：V1.2.X 含调试能力的完整分发包控制在 200 MB 级，较 V1.1.X 的 700 MB+ 实现约 70% 的体积缩减。

    .NET Runtime & WPF MIT License 完全兼容

    生命周期变更
    • 协议升级：项目开源协议从 V1.1 更新至 V1.2，全面适配 C# 技术栈的宽松授权要求
    • 旧版终止支持：V1.0.X（C#）与 V1.1.X（Python）即日起正式终止维护，过渡期结束
    • Release 下架：GitHub Releases 中上述版本的发布包将同步移除
    • 兼容性说明：以前的「验证引擎完整性.bat」仍旧可用并兼容，无需删除

    1. 渲染性能优化

    V1.1.2 (2026/5/12) — 启动器功能优化

    1. 功能调整
    • 正式版（Shiori.exe）：移除了 F12 快捷键功能，相关选项和快捷键已统一整合至「调试」菜单中
    • 调试版（Shiori_debug.exe）：新增「调试」功能模块：
      • 从头开始：仅适用于 scenes 文件夹内的剧本文件，可重新加载指定文件并重置代码执行状态
      • 加载指定文件：通过弹窗直接选择剧本文件，引擎将立即加载并运行所选文件
    2. 问题修复
    • 修复了 F10/F11/F12 快捷键失效的问题
    • 解决了从 F11（全屏）切换回 F10（窗口化）时，以及通过 UI 菜单最大化窗口时，窗口被导航栏遮挡的显示异常
    3. 性能优化
    • 优化了 CG.html 页面的图片加载机制，降低缩略图分辨率并启用 GPU 加速，有效缓解卡顿现象

    V1.1.1 (2026/5/11) — 启动器重大更新

    【重要说明】
    • 1. 新版 Python 启动器已全面取代旧版启动器，旧版将逐步停止支持
    • 2. file:// 协议模式已完全停止支持，请勿直接双击 HTML 文件运行
    • 3. 部分核心功能（如视频播放、存档管理等）无法在 file:// 模式下正常工作

    过渡期说明：由于新版启动器仍处于测试阶段，可能存在未知问题。在正式宣布完全停用旧版启动器之前，我们仍会继续提供旧版启动器的相关优化与 bug 修复服务。



    1. 系统架构变更
    • 新版启动器改为多文件运行模式。虽然文件总大小有所增加，但显著提升了运行与启动速度
    • 部署说明：请将 Shiori\dist 目录中的所有内容复制粘贴到项目根目录即可
    2. 功能新增
    • 窗口比例锁定：支持 16:9 和 4:3 两种长宽比模式，并提供常用分辨率预设，可通过菜单按需调整
    • 菜单集成：新版启动器菜单中集成了相关链接的快速访问入口
    • 引擎完整性验证：新增「验证引擎完整性.bat」工具，用于检测基本引擎文件架构，开发者可根据需求自定义修改
    3. 问题修复
    • 视频播放修复：修复了新版启动器无法播放视频的问题（Python 端推荐使用 WebM 格式 VP9 编码，HTML 端保持原有 H.264 格式不变）
    • 快捷键冲突修复：解决了 F5 快捷键冲突问题，现在 F5 绑定为快速保存存档功能
    • 进程残留修复：修复了关闭独立窗口后进程残留导致存档读取失败的问题，退出游戏后将自动静默运行 check_process.bat 清理后台进程

    V1.1.0 (2026/5/9) — 启动器技术栈全面升级

    1. 技术栈迁移
    • 启动器从 C# (.NET) 迁移至 Python (PyQt6 + QtWebEngine)
    • 内置 Chromium 内核，无需外部浏览器，兼容性更好
    2. 单文件打包
    • 新版启动器采用单文件打包（约 200MB+）
    • 包含所有 Python/Qt 依赖，只需复制 exe 文件即可运行
    3. 启动器放置位置说明
    • 新版启动器（Python/PyQt6）：放置在项目根目录（与 shiori engine 文件夹同级），运行 Shiori.exe 即可
    • 旧版启动器（C#/.NET）：放置在 shiori engine/ 文件夹内（即 shiori engine/shiori.exe），仍可按原有方式正常使用
    • 两个版本的启动器可同时存在，互不影响
    4. 重要提示
    • 新版启动器要求引擎文件夹必须命名为 shiori engine（全小写，中间有空格）
    • 不可更改为其他名称，否则启动器将无法找到引擎入口文件
    5. 完全兼容旧版开发方式
    • 游戏内容（HTML/场景/资源）的修改方式与之前完全一致
    • 无需改变开发习惯
    6. 版本信息
    • 启动器版本跃升至 V1.1.0
    • 该启动器还在测试阶段，可能会存在一些 bug
    • 日后更新的重心会侧重于新版的启动器
    • 详情请参照 README_BUILD.md 文档
