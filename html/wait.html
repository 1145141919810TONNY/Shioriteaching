[wait time] 标签使用指南

掌握自动等待与序列控制的核心用法

    1. 基础语法

    标签格式

    [wait time=${number}]

    其中 ${number} 表示毫秒（1秒 = 1000毫秒），应写为正整数。

    正确示例

    [wait time=1000]      // 等待1秒
[wait time=5000]      // 等待5秒
[wait time=10000]     // 等待10秒

    需要留意的写法

    [wait time]           // 没有数值 → 变成「点击等待」，等玩家点击才继续
[wait time=abc]       // 非数字 → 按 0 处理，实际落到默认 1000ms
[wait time=0]         // 零值 → 同样落到默认 1000ms
[wait time=-1000]     // 负数 → 定时器立即触发，相当于不等待

    2. 标签格式要求

    1. 带 time 才是定时等待：只写 [wait]、或 time 的值解析为空（例如 [wait time]）时，走的是「点击等待」——等玩家点击才继续，而不是定时。
    2. 数值用正整数：0 与非数字都会被按 0 处理、最终落到默认的 1000ms；负数会让定时器立即触发（几乎等于不等待）。
    3. 空格写法：time=1000 与 time = 1000 都支持；但 time= 1000（等号后加空格）在 command 里会被解析成空值、退化为点击等待，请避免。
      • [wait time=1000]
      • [wait time =1000]
      • [wait time = 1000]

    3. 核心功能

    基本行为

    • 暂停执行：标签会暂停当前元素的操作
    • 自动继续：等待指定时间后自动执行下一个操作
    • 无需交互：与 [s] 标签不同，不需要用户点击

    点击跳过

    • 等待期间点击屏幕，会立即结束当前的等待
    • 点击触发的是「跳过这一行」：引擎会先中断该行所有元素的等待序列（background / bgm / se / audio / chars / command 等），再进入下一行
    • 因此不只是被点击的那个元素会提前结束——同一行里其它还在等待的元素也会一起被跳过

    4. 各元素类型实现

    Command 元素

    作用：作为全局计时器，影响整个行

    语法：

    {
    command: "[wait time=1000]"
}

    单独使用（空文本）：

    {
    text: "",
    command: "[wait time=1000]"
}

    特点：

    • 等待结束后自动进入下一行
    • 不阻塞 chars 处理
    • 点击可立即跳过

    示例：

    {
    text: "等待3秒后继续...",
    command: "[wait time=3000]"
}

    Background 元素

    作用：背景图片切换序列

    语法：

    background: "bg1,[wait time=1000]bg2,[wait time=2000]bg3"

    执行流程：

    1. 显示 bg1
    2. 等待 1000ms
    3. 显示 bg2
    4. 等待 2000ms
    5. 显示 bg3

    支持转场指令：

    background: "bg1,[wait time=1000]转场 bg2,[wait time=2000]左滑 bg3"

    完整示例：

    {
    text: "背景切换测试",
    speaker: "系统",
    background: "bg_001_00_00,[wait time=1000]bg_002_00_00,[wait time=2000]bg_003_00_00"
}

    BGM 元素

    基础用法：

    bgm: "bgm1,[wait time=10000]bgm2"

    执行流程：

    1. 立即播放 bgm1
    2. 等待 10000ms
    3. 淡入播放 bgm2

    淡入播放（扩展语法）：

    // [wait time] 后跟着 BGM 名称时，执行淡入效果
bgm: "[wait time=2000]bgm1"  // 等待2秒后淡入播放 bgm1

    淡出停止（扩展语法）：

    // bgm stop[wait time=XXX] 格式：淡出指定时间后停止
bgm: "bgm stop[wait time=2000]"  // 2秒内淡出停止

    常用组合：

    // 播放BGM，等待后切换到另一个BGM
{
    bgm: "bgm1,[wait time=10000]bgm2"
}

// 淡入播放新BGM
{
    bgm: "[wait time=2000]bgm1"
}

// 淡出停止当前BGM
{
    bgm: "bgm stop[wait time=1500]"
}

    Audio 元素

    基础用法：

    audio: "audio1,[wait time=2000]audio2,[wait time=2000]audio3"

    停止播放：

    audio: "stop"  // 立即停止当前语音

    执行流程：

    1. 播放 audio1
    2. 等待 2000ms
    3. 播放 audio2
    4. 等待 2000ms
    5. 播放 audio3

    完整示例：

    {
    text: "语音序列测试",
    speaker: "角色A",
    audio: "voice_01,[wait time=3000]voice_02"
}

    停止示例：

    {
    text: "播放语音...",
    speaker: "角色A",
    audio: "voice_01"
},
{
    text: "立即停止！",
    speaker: "系统",
    audio: "stop"
}

    重要提示：

    • 默认情况下，音频会播放完毕
    • 只有显式使用 audio: "stop" 才会立即停止

    SE 元素

    基础用法：

    se: "SE001,[wait time=1000]SE002,[wait time=1000]SE003"

    停止播放：

    se: "stop"  // 立即停止当前音效

    完整示例：

    {
    text: "音效序列测试",
    speaker: "系统",
    se: "SE001,[wait time=1000]SE002,[wait time=1000]SE003"
}

    停止示例：

    {
    text: "播放音效...",
    speaker: "系统",
    se: "SE001"
},
{
    text: "立即停止！",
    speaker: "系统",
    se: "stop"
}

    Chars 元素

    基础用法：

    chars: "[左 lh1],[wait time=1000],[中 lh2],[右 lh3]"

    执行流程：

    1. 显示左侧立绘 lh1
    2. 等待 1000ms
    3. 显示中间立绘 lh2
    4. 显示右侧立绘 lh3

    消失指令：

    // [消失 立绘ID] 移除特定立绘
chars: "[左 lh1],[wait time=1000],[消失 lh1][中 lh2],[右 lh3]"

    完整示例：

    {
    text: "立绘序列测试",
    speaker: "角色A",
    chars: "[左 lh1],[wait time=1000],[中 lh2],[wait time=1000],[右 lh3]"
}

    立绘消失示例：

    {
    text: "立绘消失测试",
    speaker: "角色A",
    chars: "[左 lh1],[中 lh2],[右 lh3],[wait time=2000],[消失 lh2],[wait time=1000],[消失 lh3]"
}

    特点：

    • 元素持续显示，直到被 [消失] 指令移除
    • 后面的立绘出现时，前面的立绘保持可见
    • [wait time] 仅作为等待，不显示新立绘

    5. 异步处理

    多元素异步执行

    同一行中的多个元素可以同时执行独立的等待序列：

    {
    text: "123",
    speaker: "角色A",
    background: "bg1,[wait time=1000]bg2,[wait time=2000]bg3",
    bgm: "bgm1,[wait time=10000]bgm2",
    se: "SE001",
    audio: "YN100001",
    chars: "[左 lh1],[wait time=1000],[中 lh2],[右 lh3],[wait time=1000],[左前 lh4]"
}

    执行特点

    • 独立性：每个元素的等待序列独立运行
    • 并发性：背景、BGM、语音、音效、立绘可以同时进行
    • 互不阻塞：一个元素的等待不会阻止其他元素执行

    6. 点击跳过行为

    行为说明

    • 在等待期间点击，触发的是「跳过这一行」，而不是只结束某一个元素
    • 引擎会先中断当前行所有元素的等待序列（背景、BGM、语音、音效、立绘、command 等），再进入下一行
    • 所以被中断序列中还没显示的内容（例如后面的 bg2、bg3）不会再出现
    • 例外：如果点击时打字机效果还在进行，这一次点击只用来补全当前文字、不推进；文字补全后再点一次才会进入下一行

    示例

    {
    background: "bg1,[wait time=5000]bg2,[wait time=5000]bg3"
}

    点击效果：

    • 如果在第一个 [wait time=5000] 期间点击 → 该行等待序列被整体中断，bg2、bg3 都不会显示，直接进入下一行
    • 若全程不点击，才会依次显示 bg1 → bg2 → bg3，随即自动进入下一行

    7. 与旧指令的兼容性

    [s] 标签

    作用：等待用户点击后继续（阻塞式）

    与 [wait time] 的区别：

    特性 [s] [wait time]
    等待方式 需点击 自动
    阻塞性 阻塞整行 写在元素字段（background / bgm / …）里时不阻塞整行；写成 command 时会等序列走完才进入下一行
    适用场景 需要用户确认 自动播放

    [a] 标签

    作用：指定当前文字段落对应的音频

    与 [wait time] 的关系：

    • [a] 用于配合 [s] 指定音频
    • [wait time] 用于自动等待和序列控制
    • 两者可以混合使用

    8. 扩展语法

    BGM 淡入播放

    // [wait time] 后跟 BGM 名称 = 淡入播放
bgm: "[wait time=2000]bgm1"  // 等待2秒后淡入播放 bgm1

    [wait time]标签在此处将直接上位替代旧的bgm wait的标签。当然，你也可以继续使用旧的bgm wait标签。

    BGM 淡出停止

    // bgm stop[wait time=XXX] = 淡出指定时间后停止
bgm: "bgm stop[wait time=2000]"  // 2秒内淡出停止

    立绘位置

    [左 立绘ID]    // 左侧
[中 立绘ID]    // 中间
[右 立绘ID]    // 右侧

    立绘消失

    [消失 立绘ID]  // 移除指定立绘
[消失 all]     // 移除全部立绘（[消失 全部] 等价）
[渐出 立绘ID]  // 渐隐移除（[fadeOut] 等价）

    9. 注意事项

    1. 数值要求

    • 必须为正整数：0 或负数会被忽略
    • 单位为毫秒：1秒 = 1000毫秒
    // 错误
[wait time=0]      // 无效
[wait time=-1000]   // 无效
[wait time=abc]     // 无效

// 正确
[wait time=1000]    // 1秒
[wait time=5000]    // 5秒

    2. 空格处理

    // 元素字段（background / bgm / audio / se）里，以下写法都可以
[wait time=1000]
[wait time =1000]
[wait time= 1000]
[wait time = 1000]

// 写成 command 时请避开「等号后直接跟空格」
command: "[wait time=1000]"     // 正确
command: "[wait time = 1000]"   // 正确
command: "[wait time= 1000]"    // 会被解析成空值，退化为点击等待

    3. 异步执行理解

    {
    background: "bg1,[wait time=5000]bg2",
    chars: "[左 lh1],[wait time=1000],[中 lh2]"
}

    执行顺序（视觉上）：

    • 0ms: 显示 bg1, lh1
    • 1000ms: 显示 lh2（background 仍在等待）
    • 5000ms: 显示 bg2（chars 早已完成）

    4. 音频停止行为

    • 默认：音频播放完毕后自动结束
    • 显式停止：使用 audio: "stop" 或 se: "stop" 立即停止
    • 不会自动停止：进入新行不会自动停止 audio/se

    5. 立绘持续显示

    • 立绘显示后会一直保持
    • 必须使用 [消失 立绘ID] 才能移除（[消失 all] / [消失 全部] 一次移除全部）
    • 不同位置的立绘可以同时存在

    6. 点击跳过范围

    • 点击会跳过整行：先中断该行所有元素的等待序列，再进入下一行
    • 不是只结束被点击的那个元素——同一行其它还在等待的元素也会一起被跳过
    • 打字机仍在进行时，这一次点击只补全文字，不换行

    7. BGM 淡入淡出

    • 淡入：[wait time=XXX]bgmName = 等待后淡入播放，等待时长同时用作淡入时长
    • 淡出：bgm stop[wait time=XXX] = 淡出指定时间后停止
    • [wait time] 序列这条路径用 requestAnimationFrame 做平滑过渡；旧写法 bgm wait <key> 走的是定时器的等步长淡出，两条路径的实现不同

    8. Command 元素特性

    • 不阻塞 chars：立绘可以同时处理
    • 阻塞行：等待结束后才进入下一行
    • 可单独使用：配合空文本实现纯等待

    10. 错误处理

    语法错误

    错误写法 正确写法 说明
    [wait time] [wait time=1000] 没有数值 → 变成点击等待，需玩家点击才继续
    [wait time=abc] [wait time=1000] 非数字 → 按 0 处理，实际落到默认 1000ms
    [wait time=0] [wait time=1000] 零值 → 同样落到默认 1000ms
    [wait time=-100] [wait time=100] 负数 → 定时器立即触发，几乎等于不等待

    常见问题

    Q: [wait time] 没有生效？
    A: 若被当成点击等待，多半是 time 的值没解析出来（例如 [wait time]、或 command 里写成 time= 1000）；若等待时间不对，检查是否为 0 / 非数字（会落到默认 1000ms）或负数（会立即触发）

    Q: 背景没有切换？
    A: 检查背景 ID 是否正确，确认路径配置

    Q: BGM 没有淡入？
    A: 确保 [wait time] 在 BGM 名称之前

    Q: 立绘同时出现而不是依次？
    A: 确认 [wait time] 位置正确，应该在两个立绘之间

    Q: 音频没有停止？
    A: 使用 audio: "stop" 或 se: "stop" 显式停止

    11. 完整示例

    示例1：复杂场景

    {
    text: "场景描述",
    speaker: "角色A",
    background: "bg_room,[wait time=2000]转场 bg_outside,[wait time=3000]bg_beach",
    // 每段 [wait time] 的时长同时用作后面那首 BGM 的淡入时长；
    // 想让 BGM 停下来要用独立的一段 "bgm stop[wait time=2000]"，不能和曲名串在一起
    bgm: "[wait time=1000]bgm_peaceful,[wait time=3000]bgm_adventure",
    chars: "[左 角色A_普通],[中 角色B_微笑],[wait time=5000],[消失 角色B_微笑][中 角色B_难过],[wait time=3000],[消失 角色A_普通][左 前 角色C_生气]",
    se: "se_wind,[wait time=1000]se_birds,[wait time=1000]se_waves",
    audio: "voice_narration"
}

    示例2：对话场景

    // 第一段：等待后开始对话
{
    text: "",
    command: "[wait time=3000]"
}

// 第二段：角色入场
{
    text: "",
    speaker: null,
    chars: "[左 角色A_站立]"
}

// 第三段：对话
{
    text: "终于等到你了。",
    speaker: "角色A",
    chars: "[左 角色A_站立],[中 角色A_微笑]"
}

// 第四段：背景切换
{
    text: "我们去外面走走吧。",
    speaker: "角色A",
    background: "bg_room,[wait time=2000]转场 bg_garden",
    chars: "[左 角色A_微笑],[消失 角色A_站立]"
}

// 第五段：音效配合
{
    text: "（微风轻拂）",
    speaker: null,
    bgm: "bgm_nature,[wait time=5000]bgm stop[wait time=1500]",
    se: "se_wind,[wait time=2000]se_birds"
}

// 第六段：结束
{
    text: "今天真愉快。",
    speaker: "角色A",
    chars: "[左 角色A_高兴]",
    bgm: "bgm stop[wait time=2000]"
}
    延伸阅读：[wait time=…] 是写在 command 字段里的一条指令，command 字段的位置与「一行只做一件事」的规范请见 基础脚本语法与指令规范；同为指令的媒体类写法（bgm / se / background 的渐变与图层）请见 KS 宏与 DSL 语法指南 第 6 节；与 wait 常一起出现的立绘指令请见 立绘控制教程。
