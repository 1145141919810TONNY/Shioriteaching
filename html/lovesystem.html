Shiori 好感度系统详解

返回主页

Shiori 引擎内置了一套完整的好感度系统，基于 VarSpace.f.* 命名空间实现。该系统支持数值增减、条件分支路由、跨场景继承、存档持久化，并提供可选的 +X / -X 飘动动画 演出。本教程将完整讲解使用方式、与首页 index.html 的 sf.clear 联动（入口门禁）、system.js 的 F2 变量观察面板硬编码列表、底层原理、存档 JSON 结构以及常见问题。

教学约定： 为便于通用教学，本文示例统一使用 角色A / 角色B 作为占位角色名，好感度变量示例为 f.aff_a（角色A好感度）、f.aff_b（角色B好感度）、f.flag_a（角色A路线标记）等。引擎不限制变量命名，接入你自己的项目时，请把示例中的角色与变量名整体替换为你的实际命名（如 f.love、f.affA 这类缩写都只是开发者自己的约定）。
请注意：所有的示例Var...类均不要出现在实际的剧本中，在剧本中必须使用剧本的json格式。这些API接口仅能用于开发者调试阶段使用。

1. 核心概念与原理

变量分层

Shiori 的变量系统借鉴 KAG / kirikiri 的命名空间语义，分为三层：

命名空间 用途 持久化 是否进存档槽
f. 游戏变量（好感度、本局进度、本局标志位） sessionStorage 运行时镜像 + 存档槽 是
sf. 系统变量（通关解锁、跨周目标记） localStorage（跨会话留存） 否
tf. 临时变量（页面级缓存） 纯内存 否

好感度的本质

好感度本质上就是 f. 命名空间下的普通数值变量。约定俗成的命名格式：f.aff_a（角色A好感度）、f.aff_b（角色B好感度）、f.flag_a（角色A路线标记）等。引擎不限制变量名，开发者可以自由命名。

// 在剧本中直接读写
VarSpace.set('f.aff_a', 10);              // 设置
VarSpace.get('f.aff_a');                  // 读取
VarSpace.f.aff_a = 10;                    // Proxy 语法糖
VarSpace.f.aff_a += 5;                    // 增量修改

state.affinity 同步

为兼容旧版调试面板（F1），引擎在 applyAffinity() 中将 f.<flag> 同步到 state.affinity[flag]。两者数值始终一致，F1 面板读 state.affinity，剧本逻辑读 f.，互不冲突。

2. 集成方式：choice / nextScene / affinityChange / vars

好感度系统提供四种在剧本中触发变量变化的途径：选项跳转（choice）、场景跳转（nextScene）、独立好感度变化行（affinityChange） 与 剧本内直接操作变量（vars 动作）。前两者可携带 flag 与 add 字段，引擎会在跳转前自动累加好感度。

方式一：选项跳转（choice）

选项跳转是玩家可见的分支选择。每个选项可携带 flag（变量名，不含 f. 前缀）和 add（变化值，可为负数）字段：

{
    text: "",
    command: "[msgoff]",
    action: {
        type: "choice",
        choices: [
            { text: "和角色A聊天",     target: "聊天", flag: "aff_a", add: 3 },
            { text: "无视角色A",       target: "无视", flag: "aff_a", add: -2 }
        ]
    }
}

玩家点击选项后，引擎按顺序执行：

  1. 调用 applyAffinity(flag, add) → 累加到 f.aff_a
  2. 同步到 state.affinity[flag]
  3. 跳转到 target 指定的同文件标签（如 [聊天]）
  4. 从标签下一行继续执行
说明：
  • target 不含 .html 或 / 时视为同文件标签，调用 jumpToLabel()
  • target 含 .html 或 / 时视为跨文件场景，调用 goToScene()
  • flag 和 add 均为可选；不写则只跳转不增减好感度

方式二：场景跳转（nextScene）

场景跳转通常用于剧情推进到下一个场景。同样支持携带 flag 和 add：

{
    text: "（路线 A）aff_a 为真 → 此分支命中，并已 +10 好感度。",
    speaker: "系统"
},
{
    text: "",
    action: { type: "nextScene", target: "scene2.html", flag: "aff_a", add: 10 }
}

引擎执行顺序：

  1. 调用 applyAffinity(flag, add) → 累加到 f.aff_a
  2. 若 target 是跨文件场景（含 .html 或 /）：
    • 调用 VarSpace.flushF() 立即将 f. 写入 sessionStorage
    • 调用 writeSceneEntrySnapshot() 写入场景入口快照到 localStorage
    • 设置 shiori_next_scene_target 信号
    • 调用 goToScene() 跳转
  3. 若 target 是同文件标签，调用 jumpToLabel()

方式三：独立好感度变化行（affinityChange）

除跳转外，还可以在任意行独立触发好感度变化，不带跳转：

{
    text: "",
    action: { type: "affinityChange", flag: "flag_a", add: 1 }
},
{
    text: "已写入 VarSpace.f.flag_a = 1，用于触发静默分支的第二条路径。",
    speaker: "系统"
}

执行后引擎自动推进下一行，不阻塞剧情。

注意：
  • affinityChange 也会触发动画演出（+X / -X 飘动），可在 vars.js 顶部用 AFFINITY_ANIM_ENABLED = false 关闭
  • add = 0 时视为无变化，直接推进，不播放动画

方式四：剧本内直接操作变量（vars 动作）

当需要静默赋值（不播动画、不跳转）时，可以用 vars 动作直接在剧本行内读写变量。这是引擎 engine.js 内置的桥接动作，支持五种操作（op）：

// setF：写入 f.<name>（好感度 / 本局标志）
{ text: "", action: { type: "vars", op: "setF", name: "aff_a", value: 10 } }

// setSF：写入 sf.<name>（通关解锁等系统标记）
{ text: "", action: { type: "vars", op: "setSF", name: "clear", value: 1 } }

// setTF：写入 tf.<name>（临时缓存）
{ text: "", action: { type: "vars", op: "setTF", name: "tmp", value: "x" } }

// clearF：清空全部 f.*（保留 sf.*，等价于「开始新游戏」）
{ text: "", action: { type: "vars", op: "clearF" } }

// resetSystem：清空全部 sf.*（含 sf.clear，慎用）
{ text: "", action: { type: "vars", op: "resetSystem" } }
vars 与 affinityChange 的区别：
  • affinityChange：走 applyAffinity，会同步 state.affinity 并播放 +X / -X 动画
  • vars：只写 VarSpace，静默、无演出；适合初始化变量、标记路线、通关写 sf.clear 等场景
  • 引擎自带的测试剧本（scenes/scene_affinity_test.html）里，就是用 vars 动作直接初始化多个好感度变量（即 system.js 中 WATCHED_F_VARS 清单那 5 个演示命名，见第 8 节），方便在 F2 面板里观察

3. 条件分支路由

基于 f. 变量做条件分支，引擎支持两种方式：显式选择支 + 隐式静默分支。

静默分支（text 全空 = 自动判定）

当 choices 的 text 字段为空字符串时，引擎按 if / else-if / else 语义自动判定，首个命中即跳转：

{
    text: "",
    command: "[msgoff]",
    action: {
        type: "choice",
        choices: [
            { text: "", target: "路线A", flag: "aff_a", add: 10 },  // 条件1
            { text: "", target: "路线B", flag: "flag_a" },          // 条件2
            { text: "", target: "路线C", flag: "#" }                 // 兜底
        ]
    }
}

条件判定规则

  • flag: "aff_a" → 命中条件：f.aff_a !== 0 && f.aff_a !== false && f.aff_a !== undefined && f.aff_a !== null
  • flag: "#" → 兜底分支，永远命中
  • add 可选，命中时可附带数值变化
  • 按数组顺序判定，首个命中即跳转，后续不再检查

任意表达式判定（when）

除「非零即真」的 flag 判定外，choices 条目还支持 when 字段，直接写任意表达式（如 f.aff_a >= 20、sf.clear == 1），由 VarSpace.checkCondition() 求值。注意：when 与 flag 是两种互斥的判定方式——某条目写了 when 就按表达式求值；兜底条目请用 flag: "#"（恒真），不要写成 when: "#"：

{
    text: "",
    action: {
        type: "choice",
        choices: [
            { text: "", target: "好感高",   when: "f.aff_a >= 20" },
            { text: "", target: "好感普通", when: "f.aff_a >= 10 && f.mood > 0" },
            { text: "", target: "好感低",   flag: "#" }   // 兜底：恒真
        ]
    }
}
幂等设计建议： 推荐使用 flag 标记（set true）而非数值累加。例如用 f.routeA_cleared = 1 表示通关某路线，避免循环剧本重复触发导致数值异常累加。

4. 跨场景继承原理

跨文件跳转的完整流程

  1. 在 A.html 中触发 nextScene 或 choice 跨文件跳转
  2. 引擎调用 applyAffinity() 累加好感度
  3. goToScene() 中检测目标是否为系统页面（index.html / html/ 目录）：
    • 非系统页面（游戏场景）：
      1. 调用 VarSpace.flushF() → 立即写入 sessionStorage.shiori_f_runtime（绕过 150ms 防抖）
      2. 设置 sessionStorage.shiori_next_scene_target 信号
    • 系统页面：不写信号，f. 不继承（避免回到主菜单时残留旧值）
  4. 调用 saveStateSnapshot() 写入 sessionStorage.gameStateSnapshot（含 fVars 字段）
  5. 触发 window.location.href 跳转

B 页面加载时的继承流程

  1. vars.js 的 init() 检测 sessionStorage 信号：
    • 有 shiori_next_scene_target 或 archiveLoadTarget → 继承 shiori_f_runtime
    • 无信号（直接打开 URL / 启动器加载文件）→ 清零 f.，并清除旧镜像
  2. engine.js 的 init() 检测信号：
    • 有 shiori_next_scene_target → 消费信号，不使用场景入口快照（f. 已由 vars.js 继承）
    • 有 shiori_scene_entry_jump（saves.html / flowchart.html 设置）→ 从 localStorage.shiori_scene_entry_<scene> 恢复 f.
    • 无信号 → f. 保持清零
设计要点：
  • sessionStorage 标签页关闭即消失，避免跨会话残留
  • flushF() 绕过防抖立即落盘，不依赖 beforeunload（WebView2 中可能不可靠）
  • 系统页面跳转不设信号 → 回主菜单后 f. 自然清零

5. 存档 JSON 结构与存储键名

F5 快速存档或手动存档时，引擎会把当前 f. 全量深拷贝写入存档 JSON。读档时通过 VarSpace.restoreF() 恢复。

存档槽结构

所有存档存储在 localStorage.galgame_archives 中，是一个 JSON 数组：

      "pagePath": "/scenes/scene_demo_act.html",

关键字段说明

字段 用途 读档时是否使用
sceneFile 目标场景文件名（示例为引擎自带测试剧本 scene_affinity_test.html 所在目录的占位写法，请改成你自己的场景名） 是，决定跳转到哪个场景
lineIndex 存档时的剧情行号 是，作为 URL 参数 ?startLine=N
snapshot.fVars 好感度等 f. 变量快照 是，调用 VarSpace.restoreF()
snapshot.affinity 旧版好感度同步镜像 是，同步到 state.affinity
snapshot.gameVersion 存档时的引擎版本号 检测剧本更新兼容性
snapshot.nearestLabel 最近经过的标签锚点 lineIndex 失效时兜底定位

持久化键名一览

整个变量与存档系统依赖以下几个存储键（均为引擎 vars.js / engine.js 中的硬编码常量，注意不要与自己的代码冲突）：

键名 存储区 内容
shiori_sf localStorage 全部 sf.*（含 sf.clear 解锁标记），跨会话留存
shiori_f_runtime sessionStorage 当前 f.* 运行时镜像，仅跨文件跳转 / 读档时继承
galgame_archives localStorage 存档槽 JSON 数组
shiori_next_scene_target sessionStorage 跨文件跳转信号，触发 f. 继承
archiveLoadTarget sessionStorage 读档跳转信号（archive 页写入）
gameStateSnapshot sessionStorage 跳转 / 读档用的完整状态快照（含 fVars）
shiori_scene_entry_jump（sessionStorage）/ shiori_scene_entry_<scene>（localStorage） sessionStorage / localStorage saves.html / flowchart.html / story.html 跳入场景时恢复 f. 用的信号（sessionStorage）与该场景的入口快照（localStorage，每个场景文件只保留一条）

场景入口快照：每个剧本文件在存档中只会记录一条 f.

localStorage['shiori_scene_entry_<sceneFile>'] 记录的是「该场景最近一次经正常剧本流程进入时那一刻的 f.」，由 engine.js 的 writeSceneEntrySnapshot() 统一维护。规则如下：

  • 只会记录一次：键以场景文件名（<sceneFile>）区分，同一个剧本 html 文件只有一份入口快照，后写的覆盖先写的，不存在多条历史。
  • 只在正常流程写入：写入点收口在 goToScene() 的跨文件跳转分支——nextScene / choice / 静默分支最终都汇聚到这里，跳转前把当前 f. 记入目标场景的快照。直接打开 URL、从启动器「加载指定文件」等非正常流程不会写、也不会读它。
  • 下次正常进入时的幂等比较：再次经正常流程进入同一场景，会先做一次键序无关的深比较：
    • 本次 f. 与已存记录相同 → 不改变存档，保留原记录（同一路径重复进入不产生脏更新）；
    • 本次 f. 与已存记录不同 → 覆盖更新（可视为从不同选项 / 分支进入）。
// localStorage['shiori_scene_entry_scene_demo_next.html']（示意，一个场景文件一条）
{
  "fVars": { "aff_a": 13, "flag_a": 1 },   // 进入该场景那一刻的 f.，供后续从场景开头播放时接续
  "fromScene": "scene_demo_act.html",      // 从哪个场景进入
  "fromLine": 76,                          // 离开上一场景时的行号
  "timestamp": 1716000000000,
  "gameVersion": "V2.1.10"
}

这条记录的写入方与消费方如下：

角色 位置 动作
写入 engine.js writeSceneEntrySnapshot(targetScene)（goToScene() 内、跳非系统页前调用） 把 shiori_scene_entry_<sceneFile> 更新为目标场景的最新入口 f.；本次 f. 与旧记录相同则跳过不写
设信号 saves.html / flowchart.html / story.html 的 jumpToScene()（点击「从该场景开头播放」类卡片） 清除残留的 shiori_next_scene_target，设置 sessionStorage.shiori_scene_entry_jump = '1'，再跳 ../scenes/<sceneFile>
恢复 engine.js init()（非读档分支）检测到该信号 loadSceneEntryFvars() 读取快照 → VarSpace.restoreF() 恢复 f. 并同步 state.affinity → 从该场景第 0 行播放

这套入口快照与 archive.html 的行级读档（archiveLoadTarget + snapshot.fVars）相互独立：行级读档精确恢复到存档时的 lineIndex；场景入口快照用于「从场景开头播放但变量接续」。无论哪种入口，从启动器直接加载场景文件都因缺少信号而不会被这份快照污染（f. 保持清零）。

读档恢复流程

  1. archive.html 把存档写入 sessionStorage.archiveLoadTarget，跳转到 ../scenes/<sceneFile>?startLine=<lineIndex>
  2. 场景页 vars.js init() 检测到 archiveLoadTarget → 继承 sessionStorage f. 镜像
  3. engine.js init()：
    • 读取 archiveLoadTarget.snapshot 作为快照
    • 路径匹配 → isArchiveLoad = true
    • lineIndex 有效性检测：
      • 有效且版本一致 → 精确恢复到 lineIndex
      • 越界或版本不一致 → 用 nearestLabel 兜底（跳到标签下一行）
    • 调用 VarSpace.restoreF(snapshot.fVars) 恢复 f.
    • 恢复 AUTO / SKIP / 立绘 / BGM 等状态
    • 调用 buildStateFromHistory() 从 0..startLine-1 重建 BGM/BG/立绘
lineIndex 与 nearestLabel 的关系：
  • lineIndex 是首选，精确到行
  • nearestLabel 仅作兜底 —— 当 lineIndex 越界（剧本删减）或 gameVersion 不一致（剧本可能变更）时启用
  • 正常情况下读档会精确恢复到存档时的行，不会回退到最近标签

6. 动画开关

好感度变化时的 +X / -X 飘动动画（金色向上 / 红色向下）可在 vars.js 顶部全局开关：

// ★ 好感度加减动画开关（true=显示 +X/-X 飘动动画，false=关闭动画直接推进）
// 修改此常量即可全局控制，无需改动 engine.js
var AFFINITY_ANIM_ENABLED = true;

设为 false 后：

  • affinityUpShow / affinityDownShow 直接调用 nextLine()
  • 跳过音效、动画、1 秒等待
  • 好感度数值仍正常累加（由 applyAffinity 处理，不受影响）

运行时也可通过 API 切换：

VarSpace.setAffinityAnimEnabled(false);  // 关闭动画
VarSpace.isAffinityAnimEnabled();         // 查询当前状态

7. 系统变量 sf.clear、通关解锁与入口门禁

好感度体系里最常与 f. 配合使用的系统变量就是 sf.clear（通关标记）。它由 vars.js 顶部的 GATED_PAGES 硬编码 与首页 index.html 联动，控制「鉴赏页 / 特典页」等功能的解锁显示。

7.1 硬编码配置：GATED_PAGES（vars.js 第 53~59 行）

vars.js 中维护着一张「受管控的功能页面」清单，仅在通关一次（sf.clear == 1）后，这些页面才会在首页按钮中显示。该清单本身是硬编码数组，位于 vars.js 顶部：

// ---------- 入口门禁：受 sf.clear 管控的功能页面（相对站点根目录，小写）----------
// 仅在「通关一次（sf.clear == 1）」后，这些页面才会在首页按钮中显示。
var GATED_PAGES = [
    'html/bgm.html',    // BGM鉴赏
    'html/video.html',  // 视频鉴赏
    'html/cg.html',     // CG鉴赏
    'html/story.html'   // 小故事
];

接入你自己的项目时：

  • 路径写法为相对站点根目录、小写，不含前导 ./；
  • 需要新增 / 移除受管控页面，直接增删此数组即可，无需改动 index.html 的按钮属性；
  • 由数组自动派生出 GATED_BASENAMES 集合，用于「直接访问管控页时的重定向」判断。

7.2 与首页 index.html 的联动流程

整套门禁逻辑全部封装在 vars.js 的 applyPageGating() 中，页面 DOM 就绪后自动执行，分两步：

  1. 扫描入口链接：遍历页面中所有 <a href>，若命中 GATED_PAGES，则 sf.clear == 1 时显示、否则 display:none 隐藏（首页上的鉴赏按钮即由此控制）；
  2. 管控页守卫：若当前页自身就是受管控页且未解锁，直接重定向回 index.html，防止绕过首页直达。

与此同时，index.html（引擎根目录首页）里的「开始游戏」按钮点击时，会调用 VarSpace.clearF() 清空 f.*（好感度等本局变量），但保留 sf.*（通关解锁不因开新周目而丢失）。对应代码位于 index.html 中：

// 「开始游戏」按钮桥接：清空 f. 变量（新游戏）
// 不影响存档——存档独立存储在自己的槽位里
// sf. 不清，保留通关解锁等跨周目标记
// 开发者可自由修改按钮 href 指向任意场景，本逻辑只监听 id
var newGameBtn = document.getElementById('new-game-btn');
if (newGameBtn) {
    newGameBtn.addEventListener('click', function (e) {
        if (typeof VarSpace !== 'undefined' && VarSpace && VarSpace.clearF) {
            VarSpace.clearF();
            console.log('[NewGame] VarSpace.f.* cleared (sf.* preserved)');
        }
        // 不阻止默认跳转，让 href 正常生效
    });
}

7.3 剧本侧如何写入 sf.clear（通关收尾）

通关解锁标记通常放在「最终幕」的收尾行。两种等价写法，任选其一：

// 写法一：剧本 vars 动作（无演出、静默写入，推荐用于剧本文件）
{
    text: "——通关！此后 BGM / CG 鉴赏等入口将解锁。",
    speaker: "系统"
},
{
    text: "",
    action: { type: "vars", op: "setSF", name: "clear", value: 1 }
}

// 写法二：直接调用 API（用于 .js 初始化 / 调试）
VarSpace.setSF('clear', 1);      // 或 VarSpace.sf.clear = 1
VarSpace.setSF('bgm_all', 1);    // 可按需细分更多解锁标记

引擎自带的测试剧本 scenes/scene_affinity_test.html 结尾即用写法一写入 sf.clear = 1（模拟通关），回到首页后受控按钮就会显示。也可为周目制解锁拆分更细的标记，如 VarSpace.setSF('cg_routeA', 1)。

7.4 清除与重置的边界

操作 入口 影响范围
VarSpace.clearF() index「开始游戏」、剧本 vars 动作 只清 f.*（好感度清零），保留 sf.clear
VarSpace.resetSystem() 剧本 vars 动作、宿主「清除所有存档」 清空全部 sf.*（含 sf.clear），入口重新隐藏
子页面「重置进度」（saves 等） 游戏内菜单 只清游戏进度，不碰 sf.clear 系统解锁变量
C# 启动器「清除所有存档」： vars.js 同时包装了宿主通信：当检测到 C# 启动器清档（WebView2 postMessage 的 clearAllSaves 类信号，或 alert 弹窗中的清档关键词）时，自动调用 resetSystem() 并同步清掉 localStorage.shiori_sf 与存档槽，随后刷新首页门禁显示。因此「清除所有存档」会连 sf.clear 一起重置，而普通的读档 / 开新周目不会。

8. F2 变量观察面板与 WATCHED_F_VARS（system.js 第 35~41 行）

按 F2 打开的变量观察面板（右侧）由 system.js 的 createVarsPanel() / updateVarsInfo() 实现。它并不是自动显示全部变量，而是先遍历一份硬编码的观察名单 WATCHED_F_VARS（位于 system.js 第 35~41 行），把名单里的每个 f.<name> 当前值逐行显示出来。system.js 中的默认名单一共有 5 个变量（yn / yn2 / yr / trust / mood），取自引擎自带的测试剧本，仅为演示用途、并无特殊含义——变量命名完全自由：

// 硬编码：需要观察的 f. 变量名列表（只写名字，不含 f. 前缀）
// 面板会遍历此数组，读取 VarSpace.f.<name> 的当前值并显示
// —— 以下为 system.js 第 35~41 行的完整默认清单（测试剧本演示用，可按需增删）——
WATCHED_F_VARS: [
    'yn',    // 角色A好感度
    'yn2',   // 角色A好感度（次级标记）
    'yr',    // 角色B好感度
    'trust', // 信任度
    'mood'   // 心情值
],

面板的显示规则（updateVarsInfo 的行为）

  • f. 变量区：按 WATCHED_F_VARS 顺序列出对应 f.<name> 的值；尚未定义的变量显示灰色「(未定义)」。
  • 自动补全：名单之外的 f. 变量若已被写入，会归入面板底部的「— 其他 f. 变量 —」区（灰色弱化显示），因此不会漏看任何变量。
  • sf. 变量区：sf.clear 恒常显示（0 = 未通关，1 = 通关）；其余 sf. 变量仅当非零 / 非空时才显示。
接入自己的项目： 把清单里的示例变量换成你游戏里的真实命名即可。例如前面章节采用的教学约定命名 aff_a（角色A好感度） / flag_a（角色A路线标记） / aff_b（角色B好感度）： 
WATCHED_F_VARS: [
    'aff_a',  // 角色A好感度
    'flag_a', // 角色A路线标记
    'aff_b',  // 角色B好感度
    'trust',  // 信任度
    'mood'    // 心情值
],
想让某个新变量置顶显示就加进数组；不登记也会出现在「其他 f. 变量」区，只是排在下面、颜色较暗。
提示：F2 面板的开关状态会经 localStorage（键 galgame_vars_panel）持久化——上次开着面板，下次进游戏会自动弹出。若调试时不需要，按 F2 关闭即可。

10. 常见问题

Q1：为什么从启动器"加载指定文件"后好感度没有继承？

这是设计如此。直接打开 URL 或从启动器加载文件时，vars.js 检测不到 shiori_next_scene_target 信号，会清零 f. 以避免残留。只有通过游戏内的 nextScene 或 choice 跨文件跳转，或通过 saves.html / flowchart.html 显式跳入（设置 shiori_scene_entry_jump 信号），才会继承好感度。

Q2：为什么读档后回到了最近标签而不是存档行？

检查控制台日志。若出现 nearestLabel "xxx" located at line N，说明 lineIndex 越界或 gameVersion 不一致触发了兜底机制。正常情况下应该看到 lineIndex=N valid, precise restore，会精确恢复到存档行。

Q3：如何关闭 +X / -X 飘动动画？

在 vars.js 顶部将 AFFINITY_ANIM_ENABLED 改为 false，或运行时调用 VarSpace.setAffinityAnimEnabled(false)。关闭后好感度数值仍正常变化，只是不显示动画。

Q4：循环剧本重复触发会导致好感度异常累加吗？

会。如果剧本逻辑是 add: 10 数值累加，重复触发会叠加。推荐使用幂等设计：用 flag 标记（set true）而非累加。例如通关某路线时写 VarSpace.f.routeA_cleared = 1，下次判定时检查 f.routeA_cleared 是否为 true 即可。

Q5：sf.clear 是什么？它如何控制首页入口？

sf.clear 是系统级通关标记，属于 sf. 命名空间（跨会话留存，不进存档槽）。它和 vars.js 顶部 GATED_PAGES 硬编码清单、首页「开始游戏」按钮的 clearF() 联动，决定 BGM/CG/视频/小故事等鉴赏页入口是否在首页显示。完整机制见第 7 节。

Q6：如何查看当前好感度？

三种方式：

  • F1 调试面板：显示 state.affinity（与 f. 同步）
  • F2 变量观察面板：f. 区按 system.js 的 WATCHED_F_VARS 名单置顶显示，其余 f. 变量自动补在「其他 f. 变量」区；sf. 区的 sf.clear 恒常显示
  • F12 控制台：输入 VarSpace.dump()、VarSpace.log() 或 VarSpace.f.aff_a / VarSpace.getAffinity('aff_a')

Q7：为什么点击「开始游戏」后好感度归零了？

这是正确行为。首页「开始游戏」按钮（#new-game-btn）会调用 VarSpace.clearF()——新游戏只清 f.*（含好感度），但保留 sf.clear 等通关解锁。若想接续剧情，请走读档而非开始游戏。

Q8：F2 面板怎么没显示我新加的变量？

把变量名加入 system.js 顶部的 WATCHED_F_VARS 数组即可置顶显示；不加也会出现在「— 其他 f. 变量 —」区（颜色较暗），不会真的漏掉。注意该数组只写名字、不含 f. 前缀。

核心 API

// 读写
VarSpace.set('f.aff_a', 10);
VarSpace.get('f.aff_a');
VarSpace.f.aff_a = 10;                    // Proxy 语法糖
VarSpace.has('f.aff_a');                  // 是否存在

// 好感度数值（写走 applyAffinity，同步 state.affinity；读含动画无关）
VarSpace.applyAffinity('aff_a', 3);       // 累加并同步 F1 面板
VarSpace.getAffinity('aff_a');            // 读取（未定义返回 0）

// 条件判定
VarSpace.checkCondition('f.aff_a >= 20'); // 求值任意表达式
VarSpace.resolveBranch(choices);          // 解析静默分支（返回命中 target）
VarSpace.eval('f.aff_a + sf.clear');      // 低层求值

// 存档相关
VarSpace.serializeF();                  // 导出 f. 深拷贝（写入存档时）
VarSpace.restoreF(obj);                 // 从存档恢复 f.
VarSpace.clearF();                      // 新游戏：清空 f.，保留 sf.
VarSpace.flushF();                      // 立即写入 sessionStorage（跨文件跳转前）

// 系统变量
VarSpace.getSF('clear');
VarSpace.setSF('clear', 1);
VarSpace.resetSystem();                 // 清除所有存档时重置 sf.
VarSpace.refreshGating();               // sf.clear 变化后重扫首页入口

// 动画开关
VarSpace.isAffinityAnimEnabled();
VarSpace.setAffinityAnimEnabled(false);

// 调试
VarSpace.dump();                        // 打印 f. / sf. / tf. 全量
VarSpace.log();                         // 控制台输出
