1. 总览与双轨机制

Shiori 的指令系统有两条并行的执行路径。引擎在解析 / 执行入口用 typeof window.__shiori === 'object' 做探测：

  • DSL 路径：存在 window.__shiori.dsl 时，调用 dsl.compile(command).nodes 得到节点，再经 dsl.executeDslNode(node, this) 执行。
  • 旧正则回退路径：探测不到时，用 command.split(',') 切分，逐个 parseCommand 后交给 handleAction。

DSL 运行期版本号 window.__shiori.dsl.version 为 DSL1.0（shiori_dsl.js 中的 SHIORI_DSL_VERSION），宏展开深度不设上限（循环嵌套检测保留）。

指令分两类处理：

  • 有 impl 的指令：char、bgm、se、voice、background、off、quake、quake-stop 由 macro/ 下的原生 JS 实现处理。
  • 无 impl 的指令：经 lowerToAction 转成统一的 action 对象后交给引擎 handleAction。
相关文档：运行期对象的完整参数与返回值请见 引擎对外 API 参考；本页只讲“剧本里怎么写”。

2. 两种词面与解析规则

同一个指令有两种书写词面，解析器（parseField）会分别处理：

[wait time=1000]        ; bracket 词面
@pov 角色A              ; at 词面

切分规则

  • bracket：从 [ 开始，找到配对的 ]，括号内为指令体；找不到 ] 时按行尾截断。
  • at：从 @ 之后的第一个字符开始，直到遇到 [、@ 或 , 结束。
  • 不按逗号劈开指令体：, 只在字段层作为分隔 / 空白被跳过（skipWsComma）。

指令体结构（parseCallBody）

  • 第一个 token（parts[0]）始终是命令名。
  • key=value 形式写入 kv；另有两种等价写法：key = value（等号独立成 token）与 key =value（等号粘在后一个 token 头部）。
  • 其余 token 按顺序写入 args（位置参数）。

分词与取值（splitWsQuoted / coerce）

  • "..." 与 '...' 为字符串，支持反斜杠转义，内部空白不会被切断。
  • 其余 token 按空白或逗号截断。
  • 取值会被 coerce 转换：纯整数 → parseInt；true / false → 布尔；其余保持字符串。注意：想传字符串 "true" 是做不到的，它一定变成布尔值；同理 time=0100 会被转成整数 100。
  • 转换只发生在最终取值阶段，宏体内的 %name|默认值 模板字符串不参与转换（默认值可解析为整数时才存成数字）。

行内文本切分（splitInline）

文本字段中的 [s]（等待点）、[a]（点击点）与 <ruby>汉字<rt>注音</rt></ruby> 会被切分为 run 序列，其余部分为普通文本。

3. 一行剧本的编译顺序

宿主编译整场景时，每个 story 行按固定顺序产出节点（Compiler.CompileLine）：

  1. 行上的 background / bgm / se / videos 字段 → 资源节点；
  2. ops 数组（结构化指令，每项含 cmd 与其余 kv）；
  3. chars 字段（其中未注册的名字会被改写为立绘指令）；
  4. command 字段（本页主要讲解对象）；
  5. text 字段 → 文本节点；
  6. action 对象 → 分支节点。

运行期侧，resolveDslNodes 会优先复用 line._dsl.nodes 缓存，没有缓存时才调用 dsl.compile(command)。

6. 媒体类指令详解（bgm / se / voice / background / off）

这五条指令由 macro/media_impl.js 提供实现，是 DSL 路径下真正做出效果的一组指令。C# Schema 只声明参数名，真正的数值解析全部在 JS 侧完成。

6.1 音频三兄弟：bgm / se / voice

[BGM play storage=bgm1.ogg vol=80% time=1000]
[SE play storage=SE001.ogg vol=100%]
[Voice play storage=voice001.ogg vol=100%->20% time=2000]
[BGM stop time=800]
[BGM off]                 ; 等价写法，见 6.7
参数说明
op（位置参数）第一个位置参数。stop → 停止；play 或其它值 → 播放。省略位置参数且未给 storage 时同样按停止处理（光秃秃的 [BGM] 就是停止）。stop 优先：写了 stop 时 storage 会被忽略
storage资源名。含 / 或 \ 视为完整路径直接使用；否则查场景映射表（sceneData.bgm / se / audio）→ 音效额外走引擎 resolveSEPath → 兜底目录 ../assets/bgm/、../assets/se/、../assets/audio/。查表时先按原名、再去扩展名重试一次
vol相对音量。支持 80%、0.8、80（>1 且 ≤100 视为百分数；>100 一律封顶到 100%）。渐变写法 100%->20% 表示从 100% 渐变到 20%，必须同时给 time>0 才会真的渐变，否则直接落到终点值
time毫秒。停止：>0 为淡出后暂停并归零；=0 时 BGM 走引擎 stopBGM()、SE 与 Voice 直接 pause 并归零。播放：>0 且未写渐变时从 0 淡入；写了渐变时为渐变时长
  • 每通道只有一个播放器：bgm / se / voice 各对应一个 <audio>，新的播放直接替换 src，无法叠加播放两路 BGM 或两路 SE，后一条会打断前一条。
  • 最终音量 = 主音量 × 通道音量 × 指令相对音量（取自 systemModule.currentVolume 与 bgmVolume / seVolume / voiceVolume）。
  • bgm 自动循环播放，se / voice 不循环。
  • 浏览器自动播放策略拒绝 play() 时异常会被静默吞掉，不会中断剧情。

6.2 background：两种模式

[background storage=bg_002_00_00.png]                       ; 简单模式：替换底层背景
[background storage=panorama.png size=5339*3300 Ssize=1980*1080 layer=1 50% y=10% x=10% zoom=100%]
[background storage=panorama.png time=3000 90% y=50% x=50% zoom=50%]
[panorama.png off]                                          ; 移除该图层
模式触发条件行为
简单模式size、x、y、zoom、透明度位置参数、time>0、layer 一个都没出现调用引擎 setBackground(path) 直接替换底层背景，不创建图层。开销最小
图层模式上述任一项出现按 storage 名创建 / 复用一个绝对定位图层，写入尺寸、位置、透明度与过渡
只写 layer 也会进图层模式。[background storage=a.png layer=1] 没有任何变换，但因为给了 layer，它仍然新建一个图层叠在底层背景之上，而不是替换底层背景。

6.3 background 参数全表

参数写法作用
storage字符串资源名。省略时沿用上一次的背景（state.mediaLastBg），所以后续几行只改变换时可以不再重复写资源名
size宽*高图片的固有像素尺寸。它决定图层最终显示的宽高比——图层用 background-size:100% 100% 强制铺满，所以 size 的宽高比必须等于原图真实宽高比，否则画面会被拉变形
Ssize宽*高，默认 1920*1080基准分辨率（Screen size）：说明上面这组 size 数字是在多大的屏幕上量出来的。换算只取宽：scale = 背景容器宽 ÷ Ssize宽。详见 6.4
zoom50% / 150% / 0.5 / 2缩放倍率。带 % 直接除以 100（150%→1.5）；裸数字 <10 视为倍率（2→2 倍、0.5→0.5 倍），≥10 视为百分数（50→0.5）。缺省沿用上次，首次为 1
x / y10% / 0.1 / 10图层左上角相对背景容器的位置，对应 CSS left / top。不是中心点，也不自动居中——要居中得自己算：x =（容器宽 − 显示宽）÷ 2 ÷ 容器宽。缺省沿用上次，首次为 0
透明度位置参数 50% / 0.5 / 50取第一个能解析成百分比的位置参数作为 opacity。缺省沿用上次，首次为 1（完全不透明）
layer整数图层的 z-index，缺省 0。图层模式下后续调用若不写 layer，z-index 会被重置为 0
time毫秒>0 时给 left / top / opacity / width / height 加 CSS 过渡，并向调度器返回 { type:'mediaAnim', duration }——这段动画会阻塞剧情推进；=0 时立即定位
  • 尺寸分隔符支持 *、x、X、× 四种：5339*3300 与 5339x3300 完全等价。
  • 百分比解析规则（x / y / 透明度 / vol 共用）：带 % 除以 100；裸数字 >1 且 ≤100 也除以 100；>100 一律封顶到 100%；负数和 ≤1 的裸小数原样使用。
  • 图层元素带 pointer-events:none，不会挡住鼠标点击。

6.4 Ssize / size / zoom 的换算与演算

scale   = 背景容器宽 ÷ Ssize宽          ; 只取宽，高不参与换算
显示宽  = (给了 size ? size宽 × scale : 容器宽) × zoom
显示高  = (给了 size ? size高 × scale : 容器高) × zoom
left    = x × 100 %
top     = y × 100 %

Ssize 到底管什么：size 回答"这张图有多少像素"，Ssize 回答"这组像素数是在多大的屏幕下量出来的"。引擎据此把设计稿尺寸等比换算到当前窗口，因此换分辨率时不需要改 size。

把示例第一行逐项算一遍（设背景容器为 1920×1080）：

[background storage=panorama.png size=5339*3300 Ssize=1980*1080 layer=1 50% y=10% x=10% zoom=100%]

scale   = 1920 ÷ 1980        = 0.9697
显示宽  = 5339 × 0.9697 × 1.0 ≈ 5177 px
显示高  = 3300 × 0.9697 × 1.0 = 3200 px
left=10%   top=10%   opacity=0.5   z-index=1

紧接着的第二行只改了变换，其余全部沿用：

[background storage=panorama.png time=3000 90% y=50% x=50% zoom=50%]

Ssize 沿用 1980*1080 → scale 仍为 0.9697
size  沿用 5339*3300
zoom  = 50% → 0.5
显示宽  = 5339 × 0.9697 × 0.5 ≈ 2589 px
显示高  = 3300 × 0.9697 × 0.5 = 1600 px
left=50%   top=50%   opacity=0.9   3 秒过渡（返回 mediaAnim，阻塞 3 秒）
z-index：本行没写 layer → 被重置为 0
为什么要有继承规则：Ssize / size / zoom / x / y / 透明度在同图层的后续调用中都沿用上一次的值。若不做继承，第二行缺省 Ssize 会回退默认 1920，scale 从 0.9697 跳到 1.0，动画开始的瞬间画面会先跳变约 3% 再开始动。

6.5 背景资源路径解析

  1. 含 / 或 \ → 视为完整路径直接使用；
  2. 查场景映射表 sceneData.background（先按原名、再去扩展名）；
  3. 查全局配置表 BG_CONFIG_SUB（bg\ 目录）；
  4. 查全局配置表 CG_CONFIG_SUB（cg\ 目录）——背景同时兼容 bg\ 与 cg\ 两个文件夹；
  5. 兜底 ../assets/bg/ + 资源名。

6.6 图层生命周期与继承

  • 以 storage 名为唯一键：state.mediaLayers 里同名资源只会有一个图层。重复 background 同一张图是复用同一个元素，因此做不到"同一张图同时出现在两个位置"——需要复制成不同的文件名。
  • 图层元素带 class="shiori-bg-layer"、data-storage="资源名"、background-size:100% 100%、pointer-events:none，可在自定义 CSS 里按类名统一处理。
  • 窗口 resize 会自动重排：按当前容器尺寸重算所有已存在图层的像素宽高，保证可见比例不变（用 rAF 节流，同一帧只重排一次）。
  • off 移除图层后 state.mediaLastBg 不会被清空，下一次省略 storage 的 background 仍会沿用这张图。
  • 底层背景与图层是两套东西：简单模式改的是底层背景，图层模式叠的是图层，互不影响。已建好图层后再用简单模式换背景，图层仍然留在上面。
已知行为（resize 重排）：重算时 x / y 会被再乘一次 100（_mediaSpec 中保存的已是 x×100 之后的值），导致 left / top 被放大到原值的 100 倍。规避办法：需要自适应时自行监听 resize 并重新下发一次带完整 x / y 的 background 指令，不要依赖引擎的自动重排。

6.7 off 与 xxx.off 简写

  • [off storage=资源名]：移除背景图层并清理缓存记录。不会停止音频——停 BGM / SE / Voice 要用各自的 stop。
  • storage 为空或图层不存在时静默无事发生。
  • [资源名 off]：当指令名包含英文句点且第一个位置参数是 off 时，会被改写为 off storage=资源名，例如 [panorama.png off]。[panorama off]（不含句点）不会触发改写。
  • 改写发生在宏展开之后、降级之前，且优先于"未注册指令 → 立绘"的兜底，所以 [bgm1.ogg off] 不会被当成角色名。

7. 立绘指令与未注册指令简写

char 的实现把参数拼成一条立绘标签后转发给引擎 renderChars：

写法实际转发
[char who=角色A 正面 服装1 表情101][角色A 正面 服装1 表情101]
[char 角色A 正面]（位置参数）[角色A 正面]
[char who=角色A pos=左][角色A 左]（pos 追加在末尾）
  • 拼装顺序固定为 who → 位置参数（按书写顺序）→ pos，因此 pos 永远排在最后。位置参数在运行时位于 p._args。
  • 三个部分全空时返回空对象 {}，引擎 handleAction 会记录“未知动作类型”，即这条指令等于没写。
未注册指令的兜底规则：如果一个名字既不是已注册指令、也不是宏，并且带了位置参数，它会被改写成 char 指令——原名字成为第一个位置参数。这就是 [角色A 正面 服装1 表情101] 这类“角色名开头”的写法能生效的原因。该规则对 command 与 chars 两个字段同时生效。
反过来说：不带位置参数的未注册指令不会变成立绘，只会按 unknownPolicy 产生一条“未注册指令”诊断。
判定顺序：wait / s → xxx.off 改写 → 立绘兜底。也就是说 [bgm1.ogg off] 走的是 off，不会被当成角色名。

立绘修饰词（位置、缩放、动作、连续动作等）的完整语法见 立绘控制系统 与 高级立绘系统详细教学。

8. 震动指令与发抖宏

quake / quake-stop 由 macro/quake_impl.js 实现。

[quake who=角色A level=中 chan=allchar]
[quake level=大]                ; 不写 chan 时默认震 stage / ev / allchar
[quake-stop who=角色A]
[quake-stop]                    ; 停止全部震动

参数

参数说明
who角色名，目标元素为 id="char-<who>" 的立绘元素
level强度：极小/極小=8px、小=16px、中=32px（缺省）、大=56px、极大/極大=80px；未知值按“中”处理
chan通道，可用逗号或空白分隔多个：stage=角色舞台与立绘容器、ev=对话框、allchar=页面上所有立绘。规则：显式指定则按指定；未指定但给了 who 则只震该角色；两者都没给则默认 stage ev allchar

停止的匹配策略（quake-stop）

  1. 既无 who 也无 chan → 停止全部震动；
  2. who + chan 组合与记录键完全一致 → 停止该条；
  3. 只给了 who → 停止所有 who 相同的记录（忽略 chan）。
  • 立绘类元素优先走引擎原生的 applyShakeAction / stopShakeAction，其余元素注入 CSS 关键帧动画（只注入一次，样式 id 为 shiori-quake-style）。
  • 相同 who + chan 再次触发时先清理旧震动，避免动画叠加。
  • 引擎 init 与读档 loadStateSnapshot 前会自动清除所有残留震动。

10. .ks 宏定义源语法

.ks 文件由 C# KsMacroParser 解析。一个宏由 [macro name=...] 开始、[endmacro] 结束：

; 定时等待，不传 time 时默认 300 毫秒
[macro name=示例-等]
[wait time=%time|300]
[endmacro]

; 藏框一拍：藏消息框 → 等待 → 显示
[macro name=示例-藏框]
[msgoff]
[wait time=%time|400]
[msgon]
[endmacro]

形参写法

  • 形参写成 %name，默认值写在竖线之后：%name|默认值。
  • 首次出现的形参被登记为参数，类型固定为 str；默认值若可解析为整数则存为数字，否则存为字符串。
  • 同一个形参重复出现时只登记一次，后续复用。
  • 形参同样可以写在位置参数里（[角色A 正面 %face|表情101]）。
  • 登记顺序 = 首次出现顺序，它决定调用时位置参数与形参的对应关系（见 11）。扫描顺序是：先扫每条指令的命名参数（按书写顺序），再扫它的位置参数。
  • 形参不能写在指令名位置。解析器只对命名参数与位置参数做形参登记与替换，指令名是原样保留的。因此 [%storage|a.png off] 不会变成 [a.png off]，而是产生一条指令名就叫 %storage|a.png 的调用，最终按“未注册指令”处理。要参数化资源名，请写成 [off storage=%storage|a.png]。
  • 形参名与参数键名大小写不敏感（%Time 与 %time、storage= 与 Storage= 是同一个）。

宏体硬性规则

  • 宏体内只允许方括号 [] 调用。
  • 禁止 [s]（等同 wait click）。
  • 禁止无 time 的 [wait]（即禁止 [wait click]）。
  • 违反时产生编译错误，建议改写成 [wait time=%time|毫秒]。
  • 宏体内可以调用其它宏，包括本文件后面才定义的宏——装载时按顺序登记，展开时才做名字查找，因此嵌套与前置引用都不成问题。
  • 宏名不得与指令或其他宏重名（重名会抛异常，装载时转为“指令/宏重名已跳过”警告）。
  • 以 ; 开头的行是注释。注释里不要写方括号或 @——解析器只认 [ 和 @ 两种起始符，其余字符一律跳过，一旦注释里出现 [...] 就会被当成真实指令解析。

错误的影响范围是整个文件，不是单个宏。解析器内部只丢弃出错的那一个宏，但装载环节（MacroCatalog.MergeInto）一旦看到该文件产生了任何 Error，就会跳过这个文件里的全部宏。所以一个 .ks 文件里只要有一处 [wait] 漏写 time，同文件里写得再正确的宏也都不会生效。
排查建议：改完 .ks 后看 F1 调试面板的诊断列表，确认 Error 清零，再用宏清单核对宏是否都在。

11. 宏展开与参数绑定规则

参数绑定顺序（Bind / bindMacro）

按形参声明顺序（即首次出现顺序）逐个绑定，每个形参依次尝试：

  1. 具名键值（kv 中同名的值，大小写不敏感）；
  2. 下一个未消耗的位置参数（args）；
  3. 形参的默认值；
  4. 仍没有则绑定为空字符串 ""。
位置参数是“填空”而不是“对齐”。位置游标只在真正使用位置参数时才前进，所以具名与位置可以混用且不会错位：宏形参为 (a, b) 时，@宏 b=2 1 的结果是 a=1（拿第一个位置参数）、b=2（具名）。
同理，@宏 1 只给 a 赋值，b 走默认值——位置参数永远是“够谁给谁”，按形参顺序发牌。

替换规则（Substitute）

  • 只有当模板字符串的首字符是 % 时才查表替换；替换键为去掉 % 后、再转成小写的结果。
  • 否则原样返回（模板字符串本身不参与替换）——所以 a%name、x-%name 这类嵌在中间的占位符不会被替换。
  • 绑定表中没有该键时替换为空串。
  • 只替换命名参数与位置参数，不替换指令名（step.cmd 原样输出）。见 10 节“形参不能写在指令名位置”。

深度与循环

  • 展开深度不设上限：编译期 MacroExpander.MaxDepth 与运行期 MAX_MACRO_DEPTH 的深度判定均已移除，嵌套多少层都能展开。
  • 展开时维护递归栈，检测到循环报 宏循环嵌套；回溯时会把当前宏移出栈，因此“同一宏被前后两次顺序调用”不算循环。
  • 若某一步的 cmd 本身也是宏，会递归展开，并把展开结果平铺到输出。
  • 命中循环时，该次展开整体返回空——不只是跳过出错的那一步，而是这条宏调用产出的所有指令都不执行。
宏是“编译期 / 展开期”概念：展开后得到的是普通指令序列。因此宏的 level、time 等参数最终都以替换结果落到具体指令的 kv 上。

12. 宏的装载顺序

MacroCatalog.Scan(macroDir, engineRoot) 递归扫描引擎根下的 macro/，按扩展名归类后各自排序：

扩展名归类说明
.jsNativeJs原生 JS 宏，后载注入（用 __reg 自登记）
.ksKsMacros宏定义源，编译期解析
.jsonManifestsmanifest 声明宏
  • 三类文件都按站点根相对路径做不区分大小写排序，因此装载顺序可预期。
  • 只有位于引擎根目录之内（经 PathGuard.IsUnderRoot 校验）的文件才会被装载。
  • 合并进指令注册表的只有 .ks 与 .json，顺序为：先逐个 .ks，再逐个 .json；重名时输出 指令/宏重名已跳过 的警告（若注册表里已有同名宏则直接静默跳过）。
  • .js 不参与合并，它不会被解析成宏，只作为脚本注入页面（见下）。

原生 JS 脚本如何进页面

宿主（HttpServer.InjectOfficialSequence）在返回场景页 HTML 时，把 Macros.NativeJsRelative() 逐个拼成 <script src> 注入：

  1. 注入位置是页面第一个内联 <script> 之前；页面没有内联脚本时退到 </body> 之前。因此它们一定早于页面自己的逻辑执行。
  2. 注入时会先拼 engine_manifest.json 里的 official 资源（css 进 <head>、js 进同一段），再拼 macro/*.js。
  3. 按文件名去重：shiori_dsl.js 这类同时出现在 official 列表与 macro/ 的文件只注入一次；页面 HTML 里已经写过 <script src=".../同名.js"> 的也不会重复注入。
发行形态同样适用：打包成 .sgd 后磁盘上可能没有 macro\ 目录，扫描走的是“磁盘 + 容器”合并视图，macro/ 前缀下的条目照样能被枚举，宏与原生脚本都不会丢。

13. JSON manifest 宏

JsonManifestLoader 读取 macro/*.json，只处理 register[] 中 kind == "macro" 的声明：

{
  "register": [
    {
      "kind": "macro",
      "name": "示例-藏框",
      "steps": [
        { "cmd": "msgoff" },
        { "cmd": "wait", "time": "%time|400" },
        { "cmd": "msgon" }
      ]
    }
  ]
}
  • register[] 里 kind 不等于 macro 的条目被静默忽略（不报错），所以同一份 manifest 可以混放其它声明。
  • 每个 step 必须有 cmd，其余键全部作为该 step 的 kv。非字符串的 JSON 值会取其原始文本（GetRawText()），所以 "time": 400 与 "time": "400" 等价。
  • kv 值若以 % 开头，则按 %name|默认值 规则登记形参，登记顺序同 .ks。
  • manifest 形式无法写位置参数：C# 装载器只填 kv、不填 args，因此 manifest 宏只能靠具名参数与默认值。
  • 同样禁止 wait click / [s]，违规报 宏体内 wait 只允许定时推进，禁止 wait click / [s]，且整个文件的宏都被跳过。
  • steps 缺失或为空 → 该宏不会被登记（无诊断，容易误判为“宏没生效”）。
  • name 缺失报 manifest macro 缺少 name；JSON 解析失败报 manifest JSON 无效: 异常信息。

14. 原生 JS 宏注册（__reg）

运行期挂载了 window.__shiori.reg 与 window.__reg（同一个对象），提供四个方法：

方法入参作用
cmd(manifest){ name, alias | aliases }登记指令 schema
impl(spec){ cmd, run }登记实现；run(ctx, p) 返回 action 对象
alias(spec){ name, alias }给已有指令挂别名；不存在则以 name 新建
ks()—空操作（.ks 由 C# 编译期装载）

impl 的 run(ctx, p) 中，ctx 是 gameEngine，p 是该节点的 kv 参数展平后的对象。

  • 位置参数在 p._args，且只有存在位置参数时才有这个字段，取之前先判空。
  • kv 的值已经过 coerce：纯整数变 number、true/false 变 boolean，其余是字符串。
  • 除了 __reg.impl，运行期还额外提供 dsl.registerAction({name, alias, run})：它同时登记 schema 与实现，但传给 run 的 p 只有 kv，没有 _args。需要位置参数时请用 __reg.impl。
  • alias({name, alias})：命令已存在则把别名指向同一个 schema；不存在则以 name 为主名新建并把 alias 作为别名。
装载顺序决定成败。__shiori.reg 由 shiori_dsl.js 创建，因此 impl 脚本必须排在它之后。排在前面时脚本顶端的 if (!__reg …) return; 会静默退出——没有任何报错，只是功能全部失效。engine_manifest.json 里 macro/shiori_dsl.js 已排在 official 段末尾，而 macro/*.js 在其后注入，所以默认顺序是安全的；新增 impl 文件时不要把它插到 shiori_dsl.js 之前。

参考 macro/quake_impl.js：

(function (global) {
    'use strict';
    var root = global;
    var __reg = (root.__shiori && root.__shiori.reg) || root.__reg;
    if (!__reg || typeof __reg.cmd !== 'function' || typeof __reg.impl !== 'function')
        return;

    function start(ctx, p) {
        // 依据 p.who / p.level / p.chan 找到目标元素并施加震动
        return { type: 'quake' };
    }
    function stop(ctx, p) {
        // 清除震动
        return { type: 'quakeStop' };
    }

    __reg.cmd({ name: 'quake' });
    __reg.cmd({ name: 'quake-stop' });
    __reg.impl({ cmd: 'quake', run: start });
    __reg.impl({ cmd: 'quake-stop', run: stop });
})(typeof window !== 'undefined' ? window : this);
脚本被重复加载时，__shiori.dsl 会保留上一次的 hostRegistry 与 lastCompile 引用，并重新吸收宿主宏，因此热重载不会丢失宿主下发的宏。

16. 指令到动作的降级映射

lowerToAction 把节点转换成统一的 action 对象。注意：char、bgm、se、voice、background、off、quake、quake-stop 由 impl 直接处理，不走这张表。

执行顺序（executeDslNode）

  1. wait 在降级阶段就变成了 {kind:'wait', mode, ms} 节点，不是 inst 节点，因此它没有 kv / args；查 impl 时统一按 cmd='wait' 查找。
  2. 节点对应命令有 impl → 直接 impl(ctx, node)，不再走 lowerToAction；impl 返回空值时补成 {}。
  3. 没有 impl → 走 lowerToAction 得到 action，若 action 有 type 则交给引擎 ctx.handleAction(action)。

因此给已有指令挂 impl 会整体接管它，包括 wait（此时 node 只有 mode / ms，没有 kv）。

指令产生的 action
wait time={ type:'waitForTime', duration }
wait / s{ type:'waitForClick' }
fadeout{ type:'fadeOut', duration:time||1000, backgroundColor:color||'black' }
fadein{ type:'fadeIn', duration:time||1000, backgroundColor:color||'black' }
clearname / clear{ type:'clearName' }
msgoff{ type:'hideText' }
msgon{ type:'showText' }
finish{ type:'finishGame', bgColor:bgcolor||'black', duration:time||1500 }
finishwhite{ type:'finishGame', bgColor:bgcolor||'white', duration:time||1500 }
pov stop{ type:'povStop' }
pov 名称{ type:'povShow', povName }（多个位置参数会用空格拼接）
novel{ type:'novelOn' }
normal{ type:'novelOff' }
lock / 阻止{ type:'clickLock' }
free / 解锁{ type:'clickUnlock' }

impl 返回的 action 类型：{ type:'char' }、{ type:'bgm'|'se'|'voice' }、{ type:'background' }、{ type:'mediaAnim', duration }、{ type:'off' }、{ type:'quake' }、{ type:'quakeStop' }。未命中任何规则时返回 {}（引擎 handleAction 会记录“未知动作类型”）。

  • pov 特例：@pov 角色A 的位置参数会被空格拼接后写进 kv.name，@pov stop 则写进 kv.stop=true；已显式写了 name= 时位置参数不再覆盖。
  • wait / s 不产生 inst 节点，因此不出现在上表中，而是在 lowerToAction 开头就转成 waitForTime / waitForClick。

  • 宏循环嵌套: 名称（深度上限已取消，不再产生“宏展开超过 N 层”诊断）
  • 宏未闭合: 名称 / [macro] 缺少 name / 孤立的 [endmacro] / 宏体外指令已忽略: 名称
  • 指令/宏重名已跳过: 名称 / 指令重名: 名称
  • manifest macro 缺少 name / manifest JSON 无效
  • 无法读取宏文件: 文件 / 无法读取 manifest: 文件
调试建议：F1 调试面板会显示当前行的 DSL AST 与诊断（formatDslDebugBlock），并列出宏清单（formatDslCatalogBlock / getDslCatalog）。开发期可用它直接观察宏展开后的节点。
