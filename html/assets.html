资源管理与配置指南

统一管理背景、立绘、BGM、音效及视频资源的引用与配置

返回主页

目录

    核心原则：集中化管理
    Shiori 引擎采用集中化配置文件来管理所有静态资源。这种方式避免了在每个场景文件中重复硬编码路径，使得资源维护更加高效且不易出错。
    所有资源配置文件均位于引擎根目录的 config/ 目录下（bg_config.js、bgm_config.js、cg_config.js、cg_load_strategy.js、illustration.js）。
    这些文件由启动器按 engine_manifest.json 自动注入到页面，场景文件里手写同名引用会被剔除后重新注入，不会重复加载，因此在场景中引入只是可选写法。

    1. 背景图片 (Backgrounds)

    背景图片统一存放在 assets/bg/ 目录中。

    配置方式：

    在场景文件头部引入 config/bg_config.js，该文件定义了 BG_CONFIG 与 BG_CONFIG_SUB 对象（前者为根目录路径，后者为子目录路径）：

    <script src="../config/bg_config.js"></script>

    配置文件示例 (bg_config.js)：

    // 子目录路径配置
const BG_CONFIG_SUB = {
    'school_day': '../assets/bg/school_day.png',
    'classroom_night': '../assets/bg/classroom_night.png'
};

    剧本中使用：

    const sceneData = {
    background: BG_CONFIG_SUB, // 引用集中配置
    story: [
        {
            text: "切换到学校背景",
            background: "school_day" // 直接使用配置中的键名
        }
    ]
};

    2. 背景音乐 (BGM)

    BGM 文件统一存放在 assets/bgm/ 目录中。

    配置方式：

    在场景文件头部引入 config/bgm_config.js，该文件定义了 BGM_CONFIG、BGM_CONFIG_SUB 与 BGM_MAP：

    <script src="../config/bgm_config.js"></script>

    配置文件示例 (bgm_config.js)：

    const BGM_CONFIG_SUB = {
    'theme_romantic': '../assets/bgm/theme_romantic.ogg',
    'battle_theme': '../assets/bgm/battle_theme.ogg'
};

    剧本中使用：

    const sceneData = {
    bgm: BGM_CONFIG_SUB, // 引用集中配置
    story: [
        {
            text: "播放浪漫音乐",
            bgm: "theme_romantic" // 直接使用配置中的键名
        },
        {
            text: "淡出切换 BGM",
            bgm: "bgm wait battle_theme" // 使用 wait 指令实现平滑过渡
        }
    ]
};

    3. 角色立绘 (Characters)

    立绘文件统一存放在 assets/chars/ 目录中。

    配置方式：

    在场景文件头部引入 config/illustration.js，该文件定义了 CHAR_CONFIG 与 CHAR_CONFIG_SUB 对象：

    <script src="../config/illustration.js"></script>

    配置文件示例 (illustration.js)：

    const CHAR_CONFIG_SUB = {
    'heroine_smile': '../assets/chars/heroine_smile.png',
    'hero_serious': '../assets/chars/hero_serious.png'
};

    剧本中使用：

    {
    text: "角色出现在左侧",
    chars: "[左 heroine_smile]" // 格式：[位置 资源ID]
},
{
    text: "角色A点头示意",
    chars: "[角色A 中 点头 hero_serious]" // 支持角色标识符和动作指令
}

    提示：详细的立绘指令语法（如坐标控制、动作序列）请参考 立绘控制系统教程。

    4. 音频资源 (Audio - SE/Voice)

    音效和语音文件存放在 assets/audio/ 目录中。

    零配置管理模式（推荐）：

    引擎支持音频资源零配置管理。你无需在场景中定义映射，直接使用文件名即可。

    {
    text: "播放开门声",
    audio: "door_open" // 引擎自动查找 ../assets/audio/door_open.ogg
},
{
    text: "连续播放语音",
    audio: "voice1[a]voice2" // 依次播放两个音频文件
}

    音效（SE）独立通道：

    引擎提供了独立的 se 属性用于播放音效，与 audio（语音）通道完全分离。

    优势说明：
    - 并发播放：音效和语音可以同时播放，互不干扰
    - 统一管理：所有音效文件统一存放在 assets/se/ 目录
    - 零配置加载：与语音相同，直接使用文件名即可，无需预定义映射 
    // 单独播放音效
{
    text: "点击按钮",
    se: "click"  // 自动加载 ../assets/se/click.ogg 或 .mp3
}

// 同时播放语音和音效
{
    text: "角色说话并伴随背景音",
    voice: "voice1",  // 播放语音
    se: "bg_noise"    // 同时播放环境音效
}

// 多个音效依次播放
{
    text: "连击效果",
    se: ["hit1", "hit2", "hit3"]  // 依次播放三个音效
}

    注意事项：

    • 音效文件应放在 assets/se/ 目录下
    • 支持常见音频格式：.ogg, .mp3, .wav 等
    • se 和 voice 可以同时在同一剧情行中使用
    • audio 属性主要用于语音播放

    5. 视频资源 (Video)

    视频文件存放在 assets/video/ 目录中。

    零配置管理模式（推荐）：

    与音频类似，视频也支持零配置管理。

    {
    text: "播放开场动画",
    video: "op_video" // 引擎自动查找 ../assets/video/op_video.mp4
}

    注意：视频播放时会自动停止当前 BGM，结束后需手动指定新的 BGM。

    6. CG 鉴赏图片 (CG)

    CG 图片存放在 assets/cg/ 目录中。

    配置方式：

    在场景文件头部引入 config/cg_config.js，该文件定义了 CG_CONFIG 与 CG_CONFIG_SUB 对象：

    <script src="../config/cg_config.js"></script>

    配置文件示例 (cg_config.js)：

    const CG_CONFIG_SUB = {
    'ending_cg': '../assets/cg/ending_cg.jpg',
    'special_event': '../assets/cg/special_event.jpg'
};

    剧本中使用：

    const sceneData = {
    background: BG_CONFIG_SUB, // CG 也是通过 background 属性显示
    story: [
        {
            text: "展示一张精美的 CG",
            background: "ending_cg" // 引用 cg_config.js 中的键名
        }
    ]
};

    7. UI 皮肤配置 (UI Skin)

    UI 皮肤用于替换标题页按钮、文本框、选项按钮、右键菜单等元素的默认样式。它由两部分组成：

    • 图片：放在 assets/ui/ 目录，文件名格式为 {部件或角色}_{状态}.png
    • 尺寸表：登记在 ui/ui_size.js 的 UI_SIZE_CONFIG 中，告诉引擎每张图的像素尺寸
    为什么必须登记尺寸？
    引擎不再用 OpenCV 解码图片读尺寸，而是直接读取 ui_size.js 这个纯文本配置生成 CSS，因此加载速度极快、无任何解码开销。代价是：新增图片必须手动登记尺寸，否则该部件不生效。

    7.1 三步配置流程

    第 1 步：把 PNG 放进 assets/ui/，按 {名称}_{状态} 命名。状态只有三种：normal（必有）、hover（悬停，可选）、on（激活，可选）。

    assets/ui/title_start_normal.png   // 必有的默认态
assets/ui/title_start_hover.png    // 可选，鼠标悬停态
assets/ui/textbox_normal.png       // 文本框只有 normal 态

    第 2 步：在 ui/ui_size.js 中登记尺寸。

    var UI_SIZE_CONFIG = {
    // 只登记尺寸，位置与缩放保持默认（x/y/zoom 全填 '#'）
    title_start_normal:   { sizex: 442, sizey: 64,  x: '#', y: '#', zoom: '#' },
    title_start_hover:    { sizex: 494, sizey: 131, x: '#', y: '#', zoom: '#' },

    // 需要自定义位置时：x/y 用百分比，zoom 用百分比倍率
    title_cg_normal:      { sizex: 442, sizey: 64,  x: '10%', y: '60%', zoom: '150%' },
};

    第 3 步：重启启动器。HTTP 服务在启动时读取一次 ui_size.js，改完配置不重启不会生效。

    7.2 尺寸表字段说明

    字段必填取值说明
    sizex是数字或 '#'图片原始宽度（像素）。填 '#' 表示无图片，该条目不生效
    sizey是数字或 '#'图片原始高度（像素）。填 '#' 表示无图片
    x否'10%' / '#'水平位置，基准左上角。填具体值会把元素改为 position:fixed 相对屏幕定位
    y否'20%' / '#'垂直位置，基准左上角。填具体值同样触发 fixed 定位
    zoom否'150%' / '#'缩放倍率，转成 transform:scale()。'#' 或 '100%' 为原始大小

    书写规则：

    • sizex / sizey 是数字，不加引号；x / y / zoom 是带 % 的字符串，必须加引号，默认值 '#' 也要加引号。
    • 只有 sizex 与 sizey 都大于 0 的条目才会生成样式。
    • 尺寸以 1920×1080 为基准换算成 vw / vh：442×64 的图在 1920×1080 下正好是原始像素，在 1280×720 下等比缩小，比例不变。
    • 暂时没有图片的条目：在行首加 // 注释掉，并把 sizex / sizey 填 '#'。这样既保留占位，又不会触发加载失败告警。
    • 文件名茎（title_start_normal 这部分）只允许中文、字母、数字、下划线、连字符，不能含空格与 . / \ ? # & %，也不能超过 80 字符。

    7.3 皮肤作用的两类目标

    ① PARTS（通用部件）：跨页面复用的组件，靠 ID 选择器匹配，不需要在 HTML 里写任何标记，放对图片 + 登记尺寸即可。

    部件作用需要的状态
    textbox文本框背景normal
    namebox姓名框背景normal
    choice选项按钮normal、hover
    btn顶栏通用功能按钮normal、hover
    autoAUTO 自动播放按钮normal、hover、on
    skip1快进按钮 1normal、hover、on
    skip2快进按钮 2normal、hover、on

    ② ROLES（页面角色）：具体页面上的元素，需要在 HTML 标签上写 data-ui="角色名" 才会被皮肤命中。

    <a href="scenes/scene1.html" data-ui="title_start">开始游戏</a>
    所属页面角色名（data-ui 值）状态
    标题页title_start、title_save、title_progress、title_flow、title_story、title_bgm、title_video、title_cg、title_copynormal、hover
    分页面通用sub_back、sub_returnnormal、hover
    游戏内右键菜单ctx_panel（菜单面板）、ctx_item（菜单项）panel 仅 normal；item 为 normal、hover
    CG 鉴赏页cg_item、cg_nav、cg_closenormal、hover
    BGM 鉴赏页bgm_item、bgm_ctrlnormal、hover、on
    视频鉴赏页video_item、video_ctrlnormal、hover
    小故事页story_itemnormal、hover
    进度管理页prog_act、prog_jumpnormal、hover
    存档页arc_act、arc_slot、arc_load、arc_del、arc_ownormal、hover
    流程图页flow_act、flow_nodenormal、hover
    版权信息页copy_act、copy_nav、copy_headnormal、hover

    7.4 缺图回退规则

    • 缺 hover 图 → 自动使用 normal 图。
    • 缺 on 图 → 自动使用 normal 图。
    • 整个部件 / 角色都没有图 → 保持 style.css 的默认样式，不报错。
    • 扩展名：走预加载路径（有 UI_SIZE_CONFIG）时固定按 .png 拼接；只有降级到网络探测时才按 webp → png → jpg 顺序尝试。
    • 带 data-ui 的角色元素一旦命中皮肤图，其原文字会被隐藏（color:transparent + font-size:0），所以皮肤图请自带文字或图标。唯一的例外是 BGM 鉴赏页，它保留原有文字。

    7.5 自定义文件名映射

    如果图片名不想用 {part}_{state} 的默认规则，可以在加载 ui_skin.js 之前定义全局 UI_SKIN 覆盖。值为字符串时表示"文件名茎"，值为对象时可逐个状态指定：

    var UI_SKIN = {
    textbox: 'textbox',                                            // 茎 + _状态
    auto: { normal: 'auto_off', hover: 'auto_hi', on: 'auto_on' }  // 逐状态指定
};

    注意：改了文件名茎之后，ui_size.js 里的键名也要跟着改成实际文件名（上例应写成 auto_off: {...} 而不是 auto_normal）。

    7.6 运行时调试与提醒

    接口作用
    loadUISkin({ forceReload: true })丢弃缓存强制重新探测
    resetUISkin()清除已注入的皮肤样式节点并重新探测
    ShioriUISkin.PARTS / STATES / ROLES / LATE_ROLES查看当前支持的部件、状态与角色清单
    ShioriUISkin.EXTS / PROBE_DELAYS扩展名优先级（webp/png/jpg）与探测重试延迟（200/500/1000/2000ms）
    window.__SHIORI_UISKIN_NO_AUTO = true关闭自动加载，须在 ui_skin.js 之前设置

    两个容易踩的坑：

    • ui/ui_size.js 不在 engine_manifest.json 的官方清单内，它由启动器以内联脚本注入（判定条件是页面里不含 UI_SIZE_CONFIG 字样）。千万不要在页面里手写 <script src="../ui/ui_size.js">，否则 UI_SIZE_CONFIG 会重复声明导致脚本报错。
    • 游戏内右键菜单的 ctx_panel / ctx_item 由 ui/page-chrome.js 自动创建并带好 data-ui 标记。场景文件里不要手写这些容器，否则骨架构建会跳过，菜单会缺少皮肤标记。

    说明：早期版本用 assets/ui/.skin_cache.json 缓存图片尺寸（需 OpenCV 解码），已被 ui/ui_size.js 取代。若目录里仍残留该文件，可以忽略或删除。

    总结与建议
    1. 优先使用零配置：对于音频和视频，直接使用文件名是最便捷的方式。
    2. 保持命名规范：建议使用有意义的英文或拼音命名资源文件，避免使用特殊字符。
    3. 统一入口引入：资源配置统一放在 config/ 目录，由启动器自动注入，场景中无需重复引入。
    4. UI 皮肤记得登记尺寸：图片放 assets/ui/ 后，必须在 ui/ui_size.js 填写 sizex / sizey 并重启启动器才会生效。
    延伸阅读：本页是各类资源的统一入口。背景图片与 BG_CONFIG 在剧本里的用法请见 背景转场教程；立绘资源的命名与目录请见 立绘控制教程；各配置表怎么挂进 sceneData 请见 基础脚本语法与指令规范；各配置文件的装载顺序请见 引擎对外 API 参考 第 1 节。
