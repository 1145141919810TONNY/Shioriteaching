    1. 三层变量命名空间

    Shiori 的变量系统借鉴 KAG / kirikiri 的命名空间语义，按存活范围分为三层。三层共用同一套运算符与写法，区别只在「活多久、进不进存档」。

    前缀名称存放位置 / 持久化是否进存档槽
    f. 游戏变量（本局进度、好感度、标志位） sessionStorage 运行时镜像 + 存档槽 是
    sf. 系统变量（通关解锁、跨周目标记） localStorage（跨会话留存） 否
    tf. 临时变量（页面级缓存） 纯内存 否

    变量名在 $ 语句区里由引擎自行解析，允许 ASCII 字母、数字、下划线以及中日文字符，但不能以数字开头。例如 f.aff_a、sf.通关、tf.tmp1 都合法。

    相关文档：三层变量的读写时机、跨场景继承与存档 JSON 结构，请见 好感度系统详解 与 存档系统详解；本页只讲运算符与写法。

    2. 写变量的两个入口

    剧本里改变量有两条正式路径，二者写入的是同一个变量空间，区别在表达力：

    入口写法位置适合场景
    vars 动作 action 字段里的动作对象 单条赋值、清空变量、重置系统。op 取值 setF / setSF / setTF / clearF / resetSystem
    $ 变量语句区 command 字段（整段以 $ 开头） 一次写多条语句、做条件分支、复合赋值与自增 
    // 入口一：vars 动作（单条赋值）
{ text: "", action: { type: "vars", op: "setF", name: "aff_a", value: 10 } }

// 入口二：$ 变量语句区（多语句 + 条件分支）
{ text: "", command: "$f.aff_a += 5; f.flag = 1" }
    vars 动作的完整参数说明见 好感度系统详解 第 2 节方式四，action 字段本身的写法见 基础脚本语法与指令规范 第 3 节。下面先对照两个入口的异同，第 3 节起全部围绕 $ 变量语句区。

    2.1 两者一致的部分

    • 写入的是同一个变量空间。两条路径最终落到 stores.sf 里的同一个键，再经 persistSF() 防抖写入 localStorage，跨会话留存。
    • 受同一套系统变量规则约束。sf.clear 只能置 1、tf.allclear 完全不可写，两条路径都会被拦下（见 第 7 节）。
    • 都写在 text: "" 的空行上，本身不产生对白。

    2.2 四个实际差异

    差异vars 动作$ 变量语句区
    编译期校验 没有。type / op / name / value 只在运行时解释，写错要等这一行真的执行到才暴露 有。编译场景时即校验，问题写入 lines[i].diagnostics，F1 / F2 面板可查（见 第 9 节）
    行推进 这一行只有 action、没有 command，引擎不会自动换行，会停在空行等玩家点一下 这一行的 command 以 $ 开头，执行完 100ms 后自动进入下一行，玩家无感知
    能表达的操作 op 覆盖 setF / setSF / setTF / clearF / resetSystem，其中后两者是清档通道 复合赋值、自增自减、; 多语句、?条件 | 真分支 | 假分支；没有清档操作
    变量名校验 setF / setSF / setTF 按名字直接写入，名字格式不做校验 变量名必须匹配 f. / sf. / tf. 加标识符，不合法直接记 error 
    // 写法一：vars 动作。终态相同，但这一行没有 command，执行完停在空行等点击
{ text: "", action: { type: "vars", op: "setSF", name: "clear", value: 1 } }

// 写法二：$ 变量语句区。终态相同，执行完自动进入下一行
{ text: "", command: "$sf.clear = 1" }
    怎么选：
    • 只是写一两条变量，或者要调 clearF / resetSystem 这类清档操作，用 vars 动作（写法见 好感度系统详解 第 2 节方式四）。$ 变量语句区没有清档操作，例如清零 sf.clear 只能靠 resetSystem（见 第 7 节）。
    • 要一次写多条、做复合运算或条件分支，用 $ 变量语句区；好处是写错能在编译期被指出来，而且不打断玩家的点击节奏。
    • 同一行里 command 与 action 可以并存，执行顺序固定为先 command 后 action，两种写法能搭配使用。

    3. $ 变量语句区

    $ 变量语句区把一段变量操作写在 command 字段里。它由引擎自己解析执行，不执行任意 JS，因此没有注入面；也正因为它不走标签编译路径，纯网页环境下同样可用。

    3.1 引导符 $ 与语句分隔 ;

    • $ 必须引导整个 command 字段。字段中段出现的 $ 不会被解析，编译期会记一条 warn。
    • ; 分隔同组内的多条语句，按先后顺序逐条执行。
    • $ 之后没有任何语句会记一条 error。
    {
    text: "",
    command: "$f.stage = 1; f.stage += 2; f.stage++"   // 三条语句依次执行
}

    3.2 赋值与复合赋值

    赋值类运算符共 5 个，全部写作 命名空间.变量名 运算符 右值：

    运算符含义等价写法
    =直接赋值f.a = 10
    +=加上右值f.a = f.a + 10
    -=减去右值f.a = f.a - 10
    *=乘以右值f.a = f.a * 10
    /=除以右值f.a = f.a / 10

    复合赋值先读取当前值再运算。当前值若不是数字，按 0 处理；右值若不是数字，同样按 0 处理。因此 f.a *= 2 在 f.a 未定义时结果是 0。

    3.3 自增自减 ++ / --

    变量++ 与 变量-- 是 += 1 / -= 1 的简写，只接受「变量名 + 运算符」的紧邻写法：

    $f.stage++        // 等价于 f.stage += 1
$sf.runs--        // 等价于 sf.runs -= 1
    建议：跨存档累加类计数器（如 sf.runs）优先用 += 1 明示意图，避免与「一键置标记」的 flag 写法混淆；数值累加在循环剧本里容易被重复触发，改用布尔式标记 f.routeA = 1 更安全。

    3.4 占位符 ~

    单条语句写成 ~ 表示什么都不做。它的用途是在条件分支里保留一个空分支，让写法保持对称，例如「只在条件成立时清零，不成立时不动作」：

    $?f.stage >= 4 | ~ | f.stage = 0

    ~ 可以出现在语句组里的任意位置，执行时会被直接跳过，不留任何副作用。

    3.5 简写形式 x+1 / x-1

    变量名后面紧跟 +数字 或 -数字 时，按复合赋值处理，语义与写全完全一致：

    $sf.dead+1        // 等价于 sf.dead += 1
$sf.dead-1        // 等价于 sf.dead -= 1
$f.count + 2      // 运算符两侧的空格可有可无

    这种写法的适用范围比复合赋值窄：运算符只认 + 与 -，右值只能是数字字面量。sf.dead*2 会被判为无法识别的语句；右值想用变量、布尔值或字符串，仍然只能写 += / -=。建议直接写复合赋值，意图更明确，也不受这条限制。

    3.6 右值允许的写法

    运算符右侧只接受下面几类值，超出范围会记一条 error 并拒绝执行该条语句：

    右值类型写法示例说明
    数字f.a = 3、f.b = -1.5支持负号与小数
    布尔值f.flag = truetrue / false
    字符串tf.label = "结局一"必须用引号包围，单双引号均可
    变量引用f.copy = f.dead取另一个 f. / sf. / tf. 变量的当前值
    不支持算式：右值不能写成表达式，例如 f.a = 1 + 2、f.a = f.b * 2 都会被拒绝。需要计算请拆成多条语句，或用复合赋值：f.a = f.b; f.a *= 2。

    3.7 除法与除零

    /= 的右值为 0 时，语句被视为无效操作，变量保持原值不变，不会抛错、不会变成 Infinity。

    4. 条件分支：?条件 | 真分支 | 假分支

    在 $ 之后紧跟 ? 即可写成条件分支，用 | 分隔三段：

    $?条件 | 真分支语句组 | 假分支语句组

// 例：通关次数达到 3 就把 grade 置 1，否则保持 0 并累加尝试次数
$?f.dead >= 3 | f.grade = 1; sf.runs += 1 | f.grade = 0; sf.runs += 1
    • ? 之后必须写出条件表达式，写成空会记一条 error。
    • 假分支可以省略：$?f.stage < 0 | f.onlyThen = 1 表示条件成立才执行，不成立时整段什么也不做。
    • | 最多出现两次（即最多三段）。写成四段及以上会记一条 error。
    • 条件写成 # 表示恒真，等同于无条件执行真分支。

    4.1 | 与 || 的区别

    | 是分支分隔符，|| 是逻辑或运算符。为了不让条件里的 || 被误当成两段，引擎在切分时把成对的 || 当作一个整体（按顶层切分），因此下面这条能正确工作：

    $?f.a == 1 || f.b == 2 | f.hit = 1

    条件里的 || 保持原样参与逻辑求值，只有单独出现、不成对的 | 才起分段作用。

    5. 条件表达式与白名单

    条件表达式的最终求值交给 JS，因此引擎对条件区做白名单校验，只放行确定安全的写法。编译期与运行期使用同一套口径。

    5.1 允许的运算符

    类别运算符说明
    相等 / 不等== !=值比较
    大小比较> >= < <=数值比较
    逻辑运算&& || !与 / 或 / 非
    分组( )改变求值优先级

    除此之外，条件里只能出现三个命名空间下的变量与数字字面量。f. / sf. / tf. 在条件中直接书写，无需前缀标记。

    $?sf.clear == 1 && f.aff_a >= 20 | f.route = 1
$?!(f.mood < 0) && (f.stage > 2 || f.dead == 0) | f.ok = 1

    5.2 条件区里的 = 按 == 处理

    在 JS 里 = 是赋值而不是比较。若条件里误写单个 =，引擎会把它归一化为 ==，并记一条 warn 提示改写法：

    $?f.dead = 3 | f.eqCheck = 1 | f.eqCheck = 0
// 条件里的 f.dead = 3 已按 f.dead == 3 处理（等价比较）
// 真分支 / 假分支里的 = 仍是正常赋值

    位置语义的界线很清楚：条件区里的 = 是比较，分支体里的 = 是赋值。

    5.3 白名单之外的写法

    条件里出现全角符号或其他不受支持的片段时（常见于从文档里复制的 ≥ ≤ ＝ ＜ 以及全角括号），该条件会直接判为失败，并记一条 error 诊断：

    $?f.dead ≠ 3 | f.bad = 1 | f.bad = 999
// ≠ 不在白名单 → 条件不成立，直接走假分支，并在 F1/F2 面板记一条 error
    为什么必须显式报错：条件求值失败若被静默吞成 undefined，剧本表现会变成「这个分支永远走兜底」，极难反查。引擎因此把失败路径统一改成「条件不成立 + 记一条 error + 画面上提示一次」，保证问题可见。

    6. 分支项写法：when / flag / #

    除了 $ 语句区里的 ? 条件，choices 选项与 action 数组里的每个分支项也支持条件判定。判定按优先级取第一条成立的：

    写法判定方式
    when: "表达式"按条件白名单求值，与 $ 条件同一套规则
    flag: "#" 或 target: "#"恒真，用作兜底项
    flag: "名称"读 f.<名称>，非 0、非空、非 false 即命中
    都不写恒真

    action 字段写成数组时表示一条 else-if 链：下标即求值顺序，取首个命中项作为本行动作，其余整体跳过。省略 when 的分支项恒真，会遮蔽它后面的分支，因此应放在链末。编译期会校验：链末缺少兜底项、兜底项不在末位、空数组都会给出诊断。

    {
    text: "",
    action: [
        { when: "f.aff_a >= 20", type: "nextScene", target: "结局A.html" },
        { when: "f.aff_a >= 10", type: "nextScene", target: "结局B.html" },
        { flag: "#",              type: "nextScene", target: "结局C.html" }   // 兜底，放链末
    ]
}

    7. 系统变量的写入限制

    两个系统变量有硬性写入规则，$ 语句区、vars 动作与直接调用 API 三条路径都会拦截：

    变量规则越界时的表现
    sf.clear 通关标识，只能置 1。重复置 1 幂等，不报错；0 只是默认状态，不允许由剧本回退 记 error 诊断并拒绝写入，变量保持原值
    tf.allclear 宿主调试开关（「开启全部鉴赏」），剧本不可写。打开后对变量与分支的影响见 7.1 记 error 诊断并拒绝写入 
    $sf.clear = 1        // 合法：标记已通关一次
$sf.clear = 0        // 拒绝：0 只是默认值，不允许回退
$sf.clear = 2        // 拒绝：取值越界
$tf.allclear = 1     // 拒绝：宿主调试开关，剧本不可写
    为什么是单向的：通关是既成事实，不允许「通关之后再走一段剧情就撤销解锁」。清零的唯一通道是「清除存档」/ 宿主清档信号（resetSystem），它直接重建 sf. 存储区，不经过普通写入，属设置里的特殊功能。

    7.1 tf.allclear 与变量运算的交互

    tf.allclear 是宿主调试菜单「开启全部鉴赏」的开关（管理器与 debug 版启动器），写入 1 后靠 sessionStorage 承载键跨页面生效。剧本与插件都写不了它：$tf.allclear = 1、VarSpace.setTF('allclear', 1) 一律被拒绝并记一条 error 诊断，只有该调试菜单能写。

    它打开之后只接管「分支怎么走」，不改变「变量是什么」。逐一说明：

    对象打开 tf.allclear 后的行为
    $ 变量语句区（含 ?条件 | 真 | 假） 照常执行。变量该写什么写什么，? 条件分支也照常自动判定，语句区里没有任何 allclear 分支
    action 数组（else-if 链） 被接管。不再自动取首个命中项、也不自动跳转，全部候选逐条列成按钮，点哪条执行哪条
    静默选项组（text 全空，或写了 silent: true） 被接管。不再按序求值后自动跳转，每条选项列成按钮；点击后的结算与交互模式一致（记已读、应用 flag + add、跳转 target）
    文字非空的普通 choice 不受影响，本来就是玩家点
    入口门禁、鉴赏页锁定 属另一条线：sf.clear === 1 或 tf.allclear 为真即放行

    被接管的两种都会停住这一行等点击，不会自动推进。按钮文字优先取分支项自己的 label；没写 label 时显示 条件 → 去向（条件为空则只显示去向），便于逐条核对每条分支究竟走向哪里。

    {
    text: "",
    command: "$f.aff_a += 5",       // 先执行：变量照常落地
    action: [                       // 后执行：平时取首个命中项，全开时列按钮
        { when: "f.aff_a >= 20", type: "nextScene", target: "结局A.html" },
        { when: "f.aff_a >= 10", type: "nextScene", target: "结局B.html" },
        { flag: "#",              type: "nextScene", target: "结局C.html" }
    ]
}

    同一行里 command 先执行、action 后执行，所以上例中 f.aff_a 的加法一定先生效；随后这条链在普通流程下按 when 自动挑一条走，在全开状态下则把三条都列出来由开发者手点。关闭开关（写 0 或删除）后立即恢复自动判定，变量也不会被回滚。

    有多条不同分支时，先让你选分支项：只要同一条 action 链里存在多条互不相同的分支（不同 when 条件指向不同去向，或末位的兜底项），全开状态下引擎不会替你自动挑一条，而是把这些分支逐条列成按钮，先由你选定走哪一条；其中某一条本身是选择组（type: "choice"）时，点中它后还会继续展开该组的选项，也就是「先选分支、再选选项」。静默选项组同理：平时按序求值后自动跳转，全开时改成每条选项各一个按钮。这样调试时能把每条分支都实际走一遍，不必反复改变量去复现。

    8. 运算符速查表

    运算符出现位置作用
    $command 字段开头引导一段变量语句区
    ;语句组内分隔多条语句
    ?$ 之后紧邻引导条件分支
    |条件分支内分隔「条件 / 真分支 / 假分支」
    =语句 / 条件分支体里是赋值；条件里按 == 处理
    += -= *= /=语句复合赋值（读原值再运算）
    ++ --语句自增 / 自减 1
    + -语句（变量名与数字之间）简写：sf.a+1 等价于 sf.a += 1，右值只能是数字
    ~语句占位符，不改变任何变量
    == !=条件相等 / 不等比较
    > >= < <=条件大小比较
    && || !条件逻辑与 / 或 / 非
    ( )条件分组，改变求值优先级
    #条件 / 分支项恒真（? #、flag: "#"、target: "#"）

    9. 错误表现与诊断

    变量与条件的写法问题分两层收集，都在 F1 / F2 调试面板里显示：

    • 编译期诊断：随每行编译结果产出，挂在 story[i].diagnostics。覆盖 $ 位置、条件白名单、action 链结构等静态可判定的问题。
    • 运行期诊断：由变量系统在求值与执行时收集，通过 VarSpace.getDiagnostics() 读取，面板里显示在 Runtime（变量 / 条件） 区。同一问题只提示一次，避免推进剧本时刷屏。
    写法问题级别引擎行为
    条件里有白名单之外的内容error条件判失败（走假分支），记诊断
    条件区里写了单个 =warn按 == 处理并记诊断
    右值不受支持（算式等）error该条语句被跳过，其余语句照常执行
    变量语句位写了 ==error该条语句被跳过（赋值请用 =）
    改写 sf.clear / tf.allclearerror拒绝写入，变量保持原值
    字段中段出现 $warn该 $ 不被解析
    action 链缺兜底 / 兜底不在末位warn照常执行，提示补兜底项

    脚本里一句话写错，不会导致整段静默失效：已解析出的合法语句照常执行，出问题的语句单独被跳过。

    10. 完整示例（语法速览）

    下面这段覆盖了赋值、复合赋值、自增、变量引用、条件真假分支、~ 占位、条件里 = 按 == 处理以及系统变量限制：

    // 初始化
{ text: "", command: "$f.stage = 0; f.copy = 0; f.grade = 0; f.eqCheck = 0; f.bad = 0" }

// 赋值 / 复合赋值 / 自增
{ text: "", command: "$f.stage = 1" }
{ text: "", command: "$f.stage += 2; f.stage++" }          // 结果 4

// 变量引用
{ text: "", command: "$f.copy = f.dead" }

// 条件真假分支：条件成立走真分支，否则走假分支
{ text: "", command: "$?f.dead >= 3 | f.grade = 1; sf.runs += 1 | f.grade = 0; sf.runs += 1" }

// ~ 占位：条件成立才清零，不成立不动作
{ text: "", command: "$?f.stage >= 4 | ~ | f.stage = 0" }

// 只写真分支，省略假分支
{ text: "", command: "$?f.stage < 0 | f.onlyThen = 1" }

// 条件区里的 = 按 == 处理
{ text: "", command: "$?f.dead = 3 | f.eqCheck = 1 | f.eqCheck = 0" }

// 系统变量：只能置 1
{ text: "", command: "$sf.clear = 1" }

// 白名单之外的写法：条件不成立，记 error，走假分支
{ text: "", command: "$?f.dead ≠ 3 | f.bad = 1 | f.bad = 999" }

    上例执行完毕后各变量终值：f.stage = 4、f.copy = 3、f.grade = 1、f.eqCheck = 1、f.onlyThen 未定义、f.bad = 999、sf.runs = 1、sf.clear = 1；其中两处写法问题（条件里的单个 = 按 == 处理、条件里的 ≠ 不受支持）会各记入诊断，收集方式见第 9 节。

    11. 完整案例：死亡次数与结局走向

    前一节逐条演示单个写法，这一节给出一段可以直接照抄的终局前分岔剧本：用死亡次数、信任度与通关标识三条线，把玩家分流到四个结局。案例全部使用 $ 语句区加 action 链，并演示 sf.clear 的单向语义。

    11.1 变量分工

    变量存活范围在本案例中的作用
    f.trust本存档与角色B的信任度，决定「疏离线」是否触发，也是隐藏结局的门槛之一
    sf.deadHere跨存档「当前这个死亡点是否已经记过账」的站点标记，防止同一处反复刷线路点数
    sf.dead跨存档这条线路上记过账的死亡点数，达到门槛即解锁「共感结局」
    sf.deads跨存档全游戏累计死亡次数，同一处重复死亡也计，供统计与演出文案使用
    sf.clear跨存档通关标识：只可置 1，置过就不能回退；本案例用它把隐藏结局限定为二周目
    f.ending本存档本局走的是哪条线（1 隐藏 / 2 共感 / 3 疏离 / 4 寻常），供汇合之后分流到各自的结局剧本

    三个命名空间各管一段：f. 跟着这一周目的存档走，读档重来会回到存档当时的值；sf. 跨周目留在本机，所以「累计死亡」与「通关过没有」都必须落在它上面，写成 f.clear 就丢了；tf. 关页即失，适合做本次运行内的临时标记，本案例用不到。

    f.ending 记的是「本局拿到哪个结局」，跨文件跳转时 f. 会跟着一起走，所以这里用 f. 而不是 tf. —— 汇合处的分流正需要它。

    11.2 死亡结算：同一处只记一次线路点数

    玩家从失败点重来时先走这一段。真分支负责「第一次在此处死亡」的记账，假分支只累加全游戏总数；随后再按累计次数把台词分成两种：

    // ---------- 1. 死亡结算 ----------
{
    text: "",
    // ?条件 | 真分支 | 假分支
    // 真分支：这个点还没记过账（未定义，或不是 1）→ 记上，线路点数 +1，全局次数 +1
    // 假分支：这个点已经记过账 → 只累加全局次数，线路点数不重复计
    command: "$?sf.deadHere != 1 | sf.deadHere = 1; sf.dead += 1; sf.deads += 1 | sf.deads += 1"
},

// 台词分流：全游戏第一次死亡说「倒在了这里」，第二次及以后才说「又一次」。
// sf.deads == 1 走首次分支，其余（2 次及以上）全部落进省略 when 的兜底项
{
    text: "",
    action: [
        { when: "sf.deads == 1", type: "nextScene", target: "死亡首次" },
        { type: "nextScene", target: "死亡重复" }
    ]
},

{ text: "", command: "[死亡首次]" },
{ text: "你倒在了这里。", speaker: "系统" },
// 首次分支说完就跳到收口标签，否则会顺着往下把「又一次」也念一遍
{ text: "", action: { type: "nextScene", target: "死亡汇合" } },

{ text: "", command: "[死亡重复]" },
{ text: "你又一次倒在了这里。", speaker: "系统" },

{ text: "", command: "[死亡汇合]" },

    台词不能写死成「你又一次倒在了这里」—— 玩家第一次死在这里时还没「又」过，这句话当场穿帮。所以宁可多分一次岔：用 sf.deads 判断，等于 1 走首次分支，2 次及以上的情况全部交给省略 when 的兜底项（就是 第 6 节 说的「同一条链上，兜底项管住所有剩余情况」）。两条分支各自用 nextScene 跳到 死亡汇合 收口，首次分支必须先跳走，否则顺序执行会接着把第二段台词也念一遍。

    未初始化的变量不是 0：这里判断写的是 sf.deadHere != 1，而不是 sf.deadHere == 0。剧本从未给 sf.deadHere 赋过值时它是 undefined，而 undefined == 0 在 JS 里是假，写成 == 0 会让第一次经过这里就直接走进假分支，线路点数永远加不上去。右侧链上的 sf.clear == 1 不受这条影响：未通关时 undefined == 1 本来就是假，正是想要的结果。

    门槛取 2 至 3 次比较合适。死亡次数是「玩家试错成本」的刻度：定到 5 次，多数人还没触发就放弃了；定到 1 次，等于人人都能拿到，失去区分度。

    11.3 终局分岔：一行一条 else-if 链

    四条线路写在同一个 action 数组里，数组下标即求值顺序，取首个命中项，所以条件按「由严到宽」排列，兜底项放最后一项：

    // ---------- 2. 终局前分岔 ----------
{
    text: "",
    command: "[msgoff]",
    action: [
        // if：二周目 + 这条线死够 2 点 + 信任够 → 隐藏结局
        { when: "sf.clear == 1 && sf.dead >= 2 && f.trust >= 10",
          type: "nextScene", target: "隐藏结局", label: "隐藏结局" },

        // else if：这条线死够 3 点 → 共感结局
        { when: "sf.dead >= 3",
          type: "nextScene", target: "共感结局", label: "共感结局" },

        // else if：信任太低 → 疏离线
        { when: "f.trust < 5",
          type: "nextScene", target: "疏离线",   label: "疏离线" },

        // else：兜底（省略 when 即恒真，必须放最后一项）
        { type: "nextScene", target: "寻常结局", label: "寻常结局" }
    ]
},

    省略 when 即恒真，所以兜底项只能放链尾；写在链首会把后面全部遮蔽，编译期会记一条 warn。label 平时不显示，只在调试开关打开时当按钮文字用，写上便于核对每条分支的去向。

    11.4 线路落点、通关标识与结局分流

    每条线路都用 nextScene 汇到同一个 [汇合] 标签，块与块之间才不会顺流下去；跳走之前先把自己的去向写进 f.ending，汇合之后才有依据分流。到达任一结局都算通关，所以在汇合处统一写入通关标识：

    // ---------- 3. 各线路落点 ----------
// 每段结尾都是两件事：先记下「本局走的是哪条线」，再跳到 [汇合]。
// 少了那次跳转就会顺着往下执行，把后面几条线的台词一起演完。
{ text: "", command: "[隐藏结局]" },
{ text: "她早就知道你会回来。", speaker: "角色B" },
{ text: "", command: "$f.ending = 1" },
{ text: "", action: { type: "nextScene", target: "汇合" } },

{ text: "", command: "[共感结局]" },
{ text: "你已经倒在这里很多次了。", speaker: "系统" },
{ text: "", command: "$f.ending = 2" },
{ text: "", action: { type: "nextScene", target: "汇合" } },

{ text: "", command: "[疏离线]" },
{ text: "……", speaker: "角色B" },
{ text: "", command: "$f.ending = 3" },
{ text: "", action: { type: "nextScene", target: "汇合" } },

{ text: "", command: "[寻常结局]" },
{ text: "就这样吧。", speaker: "角色B" },
{ text: "", command: "$f.ending = 4" },

// ---------- 4. 汇合：只做所有结局共同的事，不做去向判定 ----------
{ text: "", command: "[汇合]" },
{
    text: "",
    // 通关标识：只能置 1，置过之后剧本无法写回 0（设置里的「清除存档」除外）
    // 下一周目走到这里时 sf.clear == 1 成立，隐藏结局才会进入候选
    command: "$sf.clear = 1"
},
{ text: "", command: "[msgon]" },

// ---------- 5. 汇合之后：按 f.ending 分流到各自的结局剧本 ----------
// 四个结局都从同一个 [汇合] 标签往下走，到这里已经分不清谁是谁；
// 若就此收尾，本文件会继续往下执行，四个结局会一股脑淌进同一段剧本。
// 所以按前面记下的 f.ending 各跳各的 html，每个结局都有自己的落点。
{
    text: "",
    action: [
        { when: "f.ending == 1", type: "nextScene", target: "ending_hidden.html" },
        { when: "f.ending == 2", type: "nextScene", target: "ending_empathy.html" },
        { when: "f.ending == 3", type: "nextScene", target: "ending_apart.html" },
        { when: "f.ending == 4", type: "nextScene", target: "ending_normal.html" },
        // 兜底：f.ending 万一没被赋值（日后新增线路忘了写），退回寻常结局，而不是停在这一行
        { type: "nextScene", target: "ending_normal.html" }
    ]
}

    target 只要带 .html 就会被当成跨文件目标跳走，只写标签名则在本场景文件内跳转；两种写法共用同一个字段，靠字符串形状区分，不需要额外的开关。

    汇合之后必须再分一次：[汇合] 只承担「所有结局共同要做的事」（写通关标识、恢复文本框），它本身不带任何去向。四条线都跳到这里以后，谁是从哪条线来的一概看不出来 —— 就此收尾的话，同一个场景文件会继续往下跑，四个结局淌进同一段剧本，玩家也分不清自己拿到的是哪个。所以每条线在跳走之前先用 f.ending 记下身份，汇合之后再按它跳到各自的 ending_*.html。
    方向不能反：sf.clear 是本案例里唯一「只进不退」的变量。写成 $sf.clear = 0 不会清零，引擎会记一条 error 并拒绝写入；要回到未通关状态只能用设置里的「清除存档」。自定义变量（例如 sf.clear1）不受这条限制，可以自由置 0 置 1。

    11.5 几种走法的判定结果

    状态（sf.clear / sf.dead / f.trust）首个命中的分支项分支标签 → f.ending汇合后跳往
    一周目（0 / 1 / 12）第 4 项，兜底寻常结局 → 4ending_normal.html
    一周目（0 / 3 / 12）第 2 项 sf.dead >= 3共感结局 → 2ending_empathy.html
    二周目（1 / 2 / 12）第 1 项，隐藏条件三项全中隐藏结局 → 1ending_hidden.html
    二周目（1 / 4 / 3）第 2 项 sf.dead >= 3共感结局 → 2ending_empathy.html
    二周目（1 / 0 / 3）第 3 项 f.trust < 5疏离线 → 3ending_apart.html

    规则是「首个命中即止」，所以条件越严越靠前。第 4 行走法里 f.trust < 5 其实也成立，但共感项排在它前面，先被截走；第 3 行说明隐藏项放在链首是对的，否则 sf.dead = 2 命不中第 2 项，会被最后的兜底吃掉。

    「分支标签 → f.ending」这一列不是引擎给的，是各线路在跳向 [汇合] 之前自己写下的标记 —— 汇合处的分流链就靠读它决定跳哪个 ending_*.html。两条链的结论因此必须对得上：日后增删线路，分岔链与分流链要一起改，只改一处就会出现「走到了某个结局，最后却跳进另一个剧本」。

    11.6 调试开关打开时的表现

    把 tf.allclear 打开（宿主调试菜单「开启全部鉴赏」）后，本案例里两条 action 链都不再自动挑一条，而是逐条列成按钮：终局分岔链写了 label，按「隐藏结局 / 共感结局 / 疏离线 / 寻常结局」显示；汇合后的分流链没写 label，就按「条件 → 去向」显示成 f.ending == 1 → ending_hidden.html 的样子。点哪条强制走哪条，变量不会被改写，关掉开关即恢复自动判定。完整说明见 第 7.1 节。
